## Objective

Delete `Bill Pending List` and `Bill Paid List` from
`V.SMART/V.SMART.Api/Authorization/ScreenCatalogue.cs` so the compile-time catalogue matches the
**150** rows a real database holds, and prove that `ScreenRightStartupValidator` now **refuses**
an annotation naming either.

**Owner decision, 2026-08-24: option A of [KB-109](../../decisions/KB-109-q28-r65-decision-brief.md).**

## Why — the failure this closes

`ApplicationDbContext.cs:1151` seeds **152** `Screens` rows; later migrations delete **two**
(`ScreenCode` 114 and 115). Every real database holds **150**. `ScreenCatalogue.cs` still lists
all 152, with the phantoms at lines **146-147**.

`ScreenRightStartupValidator.cs:98` validates declared names against
`ScreenCatalogue.SeededScreenNames` — the same 152-name list. So today:

```
[RequireScreen("Bill Paid List")]
   → passes startup validation      (the name IS in the catalogue)
   → no Screens row exists           (deleted by migration)
   → no UserRight row can exist      (FK is to Screens.Id)
   → deny-by-default fires
   → 403 for every user, forever, with no error and no startup warning
```

**The guard gives false assurance exactly here.** It catches typos — it would reject
`"Bil Paid List"` — but not a name that is real in the catalogue and absent from the database,
because it never consults the database.

**Blast radius today is zero.** No endpoint carries either annotation; this is a trap, not an
active fault. The fix converts a silent permanent lockout into a loud boot failure.

## Scope

1. Delete the two entries from `ScreenCatalogue.cs`.
2. Add a test proving the validator now rejects `[RequireScreen("Bill Paid List")]`.
3. Update **R-65** in [KB-060](../../risks/technical-debt-register.md) to resolved, with the
   measured count.

## Out of Scope

- **Generating the catalogue from the database.** That is option B, deferred to `M2-B10` by the
  same decision. Do not start it here.
- **Making the validator query the database at startup.** Option C, explicitly rejected: it would
  stop the host booting when the database is briefly unreachable.
- Any other entry in the catalogue. The other 150 were verified against two live databases during
  the `M0-01-03` rebuild drill; leave them alone.
- Anything outside `V.SMART.Api/Authorization/` and `tests/`.

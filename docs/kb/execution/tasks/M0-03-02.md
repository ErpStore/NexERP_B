## Task Objective

Remove the database credentials that are embedded as **C# string literals** in three
source files, replace them with configuration read from environment variables or
user-secrets, delete the commented-out production alternatives beside them, and delete the
two commented-out e-Invoice / e-Way gateway credentials found in the integration services.

Then amend **KB-060 R-01**, whose action item currently names only configuration files and
therefore under-states the problem.

## Why This Task Exists

**This task exists precisely to close a gap in the risk register.**

[KB-060 R-01](../../risks/technical-debt-register.md#r-01--live-database-credentials-committed-to-source-control)
states the problem as `V.SMART.Web/appsettings.json` and `V.SMART.Api/appsettings.json`, and
its action item reads "Move configuration to environment variables / Key Vault". **That is
incomplete.** Verified on 2026-08-12 (INV-029, re-derived directly from the files today),
the identical SA password, the identical production host `154.61.76.112,1533`, and the
identical production password appear as **hardcoded C# string literals** in three more
files:

| File | Line | What is there |
|---|---|---|
| `V.SMART/V.SMART.Shared/Data/MigrationData/ApplicationDbContextFactory.cs` | 13 | Active `var connectionString = "…User Id=sa;Password=<SA password>…"` |
| `V.SMART/V.SMART.Shared/Data/MigrationData/ApplicationDbContextFactory.cs` | 14 | Commented-out production connection string (host `154.61.76.112,1533`, database `IQSMARTDEMO_DB_2025-26`, non-`sa` user, production password) |
| `V.SMART/V.SMART.Shared/Data/MigrationData/MasterDbContextFactory.cs` | 11 | Commented-out production connection string (host `154.61.76.112,1533`, database `IQSmartDb_Master`) |
| `V.SMART/V.SMART.Shared/Data/MigrationData/MasterDbContextFactory.cs` | 12 | Active `optionsBuilder.UseSqlServer("…User Id=sa;Password=<SA password>…")` |
| `V.SMART/V.SMART/MauiProgram.cs` | 228 | Commented-out production `AddDbContext<MasterDbContext>` registration |
| `V.SMART/V.SMART/MauiProgram.cs` | 231 | **Active** `AddDbContext<MasterDbContext>` registration with `User Id=sa` and the SA password |
| `V.SMART/V.SMART/MauiProgram.cs` | 235 | A third commented-out registration, host `VK-7-HP\SQLEXPRESS`, same SA password |

All three files **are in the single committed commit `c12c5b2`**, on a **public** remote
(`git grep -l "aDMIN@123" HEAD` returns all three plus
`V.SMART/V.SMART.Web/appsettings.json` — Confirmed, re-run 2026-08-12).

Two further credential literals, in comments, in the integration layer:

| File | Line | What is there |
|---|---|---|
| `V.SMART/V.SMART.Shared/BusinessLayer/BusinessService/EInvoiceAPIService/EinvoiceDatabaseService.cs` | 1413-1414 | `auth.UserName = username;//"API_…";` and `auth.Password = password;//"$Win…";` — an e-Invoice **gateway** credential left in a trailing comment |
| `V.SMART/V.SMART.Shared/BusinessLayer/BusinessService/EInvoiceAPIService/EWayDatabaseService.cs` | 900-901 | The same pattern for the e-Way gateway |

These two are a **different credential** from the database ones — they authenticate to the
GST e-Invoice / e-Way gateway, not to SQL Server. The runtime code already takes them as
method parameters (`GetUserNameandPassword(string username, string password)`), so the
literals are dead comments. They must still be deleted and must still be rotated by
**M0-04**, because they are committed to a public repository.

**Consequence for G0.** The G0 criterion is "No connection string or JWT secret in the
working tree **or** in `git grep … HEAD`". Doing M0-03-01 alone and stopping would leave
`git grep -n "Password=" -- "V.SMART/"` returning six hits across three C# files — G0 would
fail while the register said the work was done. That is the failure mode this task prevents.

## Existing Behavior to Preserve

- `ApplicationDbContextFactory.CreateDbContext(string[] args)`
  (`…/MigrationData/ApplicationDbContextFactory.cs:8-23`) and
  `MasterDbContextFactory.CreateDbContext(string[] args)`
  (`…/MigrationData/MasterDbContextFactory.cs:8-15`) are `IDesignTimeDbContextFactory<T>`
  implementations. They exist so `dotnet ef migrations add` / `dotnet ef database update`
  can construct a context without running the host. **They must keep working for EF
  tooling**, or migration authoring breaks. The `args` parameter is currently ignored;
  after this task it may be used as a connection-string source, but configuration and
  environment must remain available too.
- The MAUI host registers `MasterDbContext` via
  `builder.Services.AddDbContext<MasterDbContext>(...)`
  (`V.SMART/V.SMART/MauiProgram.cs:230-231`). The registration itself, its lifetime, and
  the rest of the ~242-registration DI graph must be untouched — only the connection-string
  source changes. (Consolidating the duplicated DI graphs is **R-26 / M2-B07**, not this
  task.)
- `EinvoiceDatabaseService.GetUserNameandPassword(string username, string password)`
  (`…/EinvoiceDatabaseService.cs:1408-1421`) and
  `EWayDatabaseService.GetUserNameandPassword(string username, string password)`
  (`…/EWayDatabaseService.cs:895-908`) already take their credentials as parameters. Delete
  the trailing comments only; **do not change the method signature or its callers.** Both
  services are 2,000+ LOC and feed INV-015, which has not run yet.
- The `#region Local / Testing ConnectionString Local/Cloud` marker at
  `…/ApplicationDbContextFactory.cs:11` may be kept or removed; it carries no behaviour.

   - `git grep -n "Password=" -- "V.SMART/"`
   - `git grep -l "aDMIN@123" HEAD`
   - `git status --porcelain`
3. Read all five source files in full before editing any of them. Confirm the line numbers
   in the table above still match; if the tree has moved under you, record the new numbers
   and proceed from the code, not from this document (KB-002 authority order: code wins).
4. **`MasterDbContextFactory.cs`** — replace the literal at line 12 and delete the comment
   at line 11. Read the connection string from the environment
   (`ConnectionStrings__MasterDb`, or `Environment.GetEnvironmentVariable`), falling back to
   an `IConfigurationBuilder` chain that includes user-secrets if the project references
   `Microsoft.Extensions.Configuration.UserSecrets`. If neither yields a value, throw an
   `InvalidOperationException` whose message names the environment variable and the
   `dotnet user-secrets set` command to run. Do **not** fall back to any default connection
   string — a silent fallback is how the current problem was created.
5. **`ApplicationDbContextFactory.cs`** — same treatment for lines 13 and 14. Note that this
   factory builds a **tenant** context; a design-time run needs *some* tenant database. Use
   a distinct key (for example `ConnectionStrings:DesignTimeTenantDb`) rather than
   overloading `MasterDb`, and document the key in the same developer note M0-03-01 created.

   delete the commented registrations at lines 228 and 235. If the MAUI host does not

   and currently holds only `UpdateSettings:SetupPath`) and how it is loaded before adding a
   new mechanism. Keep the change minimal: same `AddDbContext<MasterDbContext>` call, same
   lifetime, different string source.
7. **`EinvoiceDatabaseService.cs:1413-1414`** and **`EWayDatabaseService.cs:900-901`** —

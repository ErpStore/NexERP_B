## Task Objective

Extract the domain-service composition root that is currently duplicated across
`V.SMART.Web/Program.cs` and `V.SMART/MauiProgram.cs` into a single
`AddVSmartDomain(this IServiceCollection)` extension method living in `V.SMART.Shared`, and
call it from **all three** hosts — `V.SMART.Web`, `V.SMART` (MAUI) and `V.SMART.Api`.

After this task, adding a business service to the graph is a one-line change in one file,
and `V.SMART.Api` can resolve **any** business service by constructor injection, not just
`ICurrencyService`.

## Why This Task Exists

**This task is the linchpin of the entire M2-B stream. Nothing else in M2-B works without
it.**

`V.SMART/V.SMART.Api/Program.cs` is 118 lines long and registers exactly **one** business
service — `ICurrencyService` at line 102 (Confirmed, re-verified 2026-08-12). Meanwhile
`V.SMART/V.SMART.Web/Program.cs` is 654 lines / 34,813 bytes with **242**
`AddScoped`/`AddSingleton`/`AddTransient` occurrences, and `V.SMART/V.SMART/MauiProgram.cs`
is 640 lines / 38,572 bytes with **243**, registering the same graph independently
(Confirmed).

The practical consequence, and the reason this is P0:

> **Until `AddVSmartDomain()` exists and `V.SMART.Api` calls it, every new controller fails
> at runtime with a DI resolution error.** The build succeeds — the failure appears only
> when ASP.NET Core tries to activate the controller and cannot construct its service. A
> team can write ten controllers, see a green build, and discover the problem only on the
> first request.

Every other task in M2-B that adds or touches a controller
([M2-B01](M2-B01.md), [M2-B04](M2-B04.md), [M2-B05](M2-B05.md), [M2-B06](M2-B06.md),
[M2-B08](M2-B08.md), [M2-B09](M2-B09.md), [M2-B12-03](M2-B12-03.md)) declares this task as
a hard dependency for exactly this reason, and so does every controller task in M2-D, M3
and M4.

It also serves **R-26** ([KB-060](../../risks/technical-debt-register.md)) — *duplicated DI
composition roots*, whose recorded action item is precisely "Extract a shared
`AddVSmartDomain(this IServiceCollection)` extension in `V.SMART.Shared` and call it from
all three hosts."

**The drift R-26 predicts is already measurable (Confirmed, new finding — record it).**
The two composition roots are not identical:

| Divergence | Web | MAUI |
|---|---|---|
| Registration count | 242 (`Program.cs`) | 243 (`MauiProgram.cs`) |
| `IFileOpener` lifetime | `AddScoped` — `Program.cs:261` | **`AddSingleton`** — `MauiProgram.cs:262` |
| `ReportService` | registered once — `Program.cs:245` | registered **twice** — `MauiProgram.cs:200` and `:219` |

A `Singleton` implementation of an interface whose Web counterpart is `Scoped` is exactly
the class of defect a single composition root removes by construction.

  `V.SMART/V.SMART.Web/Program.cs:226-227`, `V.SMART/V.SMART.Api/Program.cs:82-83`
  (Confirmed).
- AutoMapper is registered by scanning the assembly containing `MappingProfileMarker`:
  `V.SMART/V.SMART.Web/Program.cs:230-233`, `V.SMART/V.SMART.Api/Program.cs:91-94`

- `ILoggingService` → `FileLoggingService` is registered in all hosts
  (`V.SMART/V.SMART.Web/Program.cs:258`, `V.SMART/V.SMART.Api/Program.cs:98`) and its

  but never the open generic). Any controller that injects `IRepository<T>` directly fails

Confidence on the claim "the API can resolve only `ICurrencyService` among business

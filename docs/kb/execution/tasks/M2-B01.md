## Task Objective

Move every route in `V.SMART.Api` under the `/api/v1` prefix mandated by
[ADR-002 §6](../../decisions/ADR-002-rest-api-layer.md#6-versioning-and-generation), and
establish the single place a future controller inherits that prefix from — so that no
controller author ever writes the version string by hand.

## Why This Task Exists

**Land it while there are two controllers, not sixty.**

Versioning touches *every* controller's route attribute. Today that is exactly two files
(Confirmed, re-verified 2026-08-12):

| Controller | Route today | Route after |
|---|---|---|
| `V.SMART/V.SMART.Api/Controllers/AuthController.cs:11` | `[Route("api/auth")]` | `api/v1/auth` |
| `V.SMART/V.SMART.Api/Controllers/CurrencyController.cs:9` | `[Route("api/currencies")]` | `api/v1/currencies` |

[KB-080 §9](../README.md#parallel-work) states the rule directly: *"`M2-B01` (versioning)
touches every controller route — land it while there are two controllers, not sixty."*
Deferring it converts a one-day edit into a cross-cutting change against 60–80 controllers
and an already-generated TypeScript client.

It is also **C3** in [KB-041's P2 hardening list](../../api/api-readiness-assessment.md#p2--hardening),
but it is scheduled in M2 rather than later precisely because its cost grows with controller
count while its value does not.

Note the asymmetry that makes this cheap now and expensive later: the Swagger document is
**already** named `v1` (`V.SMART/V.SMART.Api/Program.cs:26` —
`c.SwaggerDoc("v1", new OpenApiInfo { Title = "V.SMART API", Version = "v1" })`, Confirmed),
so the OpenAPI document already claims a version the routes do not carry. This task removes
that inconsistency before [M2-B10](M2-B10.md) generates a TypeScript client from it.

## Target Result

All six endpoints respond under `/api/v1/…` and **do not** respond under the old paths:

```
POST   /api/v1/auth/login
GET    /api/v1/currencies?pageNumber&pageSize&currName&createdBy&fromDate&toDate
GET    /api/v1/currencies/{id:int}
POST   /api/v1/currencies
PUT    /api/v1/currencies/{id:int}
DELETE /api/v1/currencies/{id:int}
```

**Mechanism: a literal route prefix plus one shared constant. No versioning library.**

Add `V.SMART/V.SMART.Api/ApiRoutes.cs` (**TO BE CREATED**):

```csharp
namespace V.SMART.Api;

public static class ApiRoutes
{
    public const string V1 = "api/v1";
}
```

and use `[Route($"{ApiRoutes.V1}/currencies")]`. That is the whole change.

**Why not `Asp.Versioning.Mvc`?** The package is not currently referenced
(`V.SMART/V.SMART.Api/V.SMART.Api.csproj` has exactly three `PackageReference` entries:
`Microsoft.AspNetCore.Authentication.JwtBearer` 9.0.5, `Microsoft.AspNetCore.OpenApi` 9.0.5,
`Swashbuckle.AspNetCore` 7.3.1 — Confirmed). A versioning library earns its keep when
multiple versions must coexist, with version negotiation, deprecation headers and
per-version OpenAPI documents. There is exactly one version, and ADR-002 does not ask for
more. Adding the library now would be infrastructure with no consumer, and it complicates
the Swagger configuration that [M2-B10](M2-B10.md) has to generate a client from.

The executing session **may** propose the library instead, but only with a written argument
in the final report, and only if it does not increase the diff beyond one day's work. If in
doubt, take the constant.

**Resource naming.** ADR-002 §2 requires plural kebab-case resources. `currencies` and
`auth` already satisfy it (`auth` is not a resource collection but is the conventional path
for the token endpoint, and ADR-002 §5 itself writes `POST /api/v1/auth/login`). No renaming
is needed. Record that as a checked-and-satisfied item, not an omission.

**Old routes are removed, not kept as aliases.** There is no external consumer to protect —
the only one is the pilot being archived. Keeping `[Route("api/currencies")]` alongside the
new route would put two paths in the OpenAPI document and therefore two method names in the
generated TypeScript client, which is a worse outcome than a clean break.

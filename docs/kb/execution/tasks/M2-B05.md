## Objective

After this task, every `storeId` argument passed to `IStockManagerService.AddOrUpdateStockAsync`
that was previously a bare integer literal (`6` or `7`) is a named `StoreIds` constant instead,
so a transposed or mistyped store id becomes a compile error rather than a silent
misattribution of stock to the wrong store.

## Scope

- A generated `V.SMART/V.SMART.Shared/Utility_Constants/StoreIds.cs` — one `const int` per row
  of the `Store` seed, plus a `Names` lookup, generated by a committed, re-runnable tool.
- Replacing the **55** confirmed bare-literal `storeId` call sites (24 × `6`, 31 × `7`) across
  7 `BusinessLayer` service files with the matching `StoreIds` constant.
- Closing risk **R-66**.

## Out of Scope

- **Not an enum.** Same reasoning R-10's original spec gave for `ScreenCodes`: the interface
  parameter is `int` and stays `int`. Converting the signature and the `StockAdd`/`StockIssue`
  persistence columns is a larger, riskier change than this task's premise calls for.
- **`IssueOrUpdateStockAsync` and `GetQtyBalQtyByStockAddAsync`** — `INV-059` confirms zero
  literal `storeId` sites in either; nothing to replace there.
- **The original `ScreenCodes`/`R-10` scope.** Falsified, not reintroduced. If a future need for
  a database-derived screen-name catalogue arises (ADR-004's `[RequireScreen("…")]` still hand-
  types its argument, and `ScreenCatalogue.cs` still hard-codes two names no database contains —
  R-65), that is a **different task**, belonging with M2-A02, not this one.
- **`V.SMART.Api/**`.** No controller work. `storeId` is not yet exposed by any endpoint.
- **A live manual stock smoke test.** See *Completion Conditions* — this is the one acceptance
  item this close-out does not satisfy, and it is called out rather than skipped silently.

## Implementation Requirements

1. **Re-verify the `Store` seed** rather than trusting this document: row count, `StoreId`
   uniqueness, `StoreName` uniqueness. (Delivered: `tools/generate-store-ids/test.mjs` asserts
   all three against the live seed on every run — 9 rows, `6`→`REJECTION STORE`,
   `7`→`REWORK STORE`.)
2. **Build the call-site inventory.** Classify every call to `AddOrUpdateStockAsync`,
   `IssueOrUpdateStockAsync` and `GetQtyBalQtyByStockAddAsync` in `V.SMART.Shared/` by what its
   `storeId` argument actually is. (Delivered: `INV-059` — 55 literal sites, 187
   variable/expression, 13 commented-out, 10 declarations/log strings, 0 ambiguous.)
3. **Write a generator, not a hand-typed file**, that parses the `Store` seed and emits
   `StoreIds.cs`, asserting and failing loudly on: a duplicate `StoreId`; a duplicate
   `StoreName`; two names collapsing to the same C# identifier; zero rows parsed. (Delivered:
   `tools/generate-store-ids/generate.mjs`, self-tested by `test.mjs` against both the real seed
   and four synthetic violation fixtures — every one raises.)
4. **Generate `StoreIds.cs`, build, confirm 0 errors before touching any call site.**
   (Delivered — see *Testing*.)
5. **Replace the 55 literal sites** with the matching constant, file by file, in a way that
   cannot touch an unrelated bare `6`/`7` elsewhere in the same file (anchored to the
   `AddOrUpdateStockAsync(` call syntax specifically) and cannot touch a commented-out call
   (line-comment-masked before matching — a first pass without this masking wrongly edited 3
   commented-out lines and was fully reverted before committing; see *Verification*).
6. **Add `using V.SMART.Shared.Utility_Constants;`** to each of the 7 touched files (none
   already had it; `ImplicitUsings` does not cover project namespaces).
7. **Prove no value changed** — a mechanical diff review confirming every `-`/`+` pair is
   identical once the constant name is substituted back for its literal digit. Non-negotiable,
   same standard M2-B05's original `ScreenCodes` spec set for its own literal replacement.
8. Build both `V.SMART.Api` and `V.SMART.Web` and confirm 0 errors.

## Verification

The value-equality diff review (55 sites, `V.SMART.Shared/` only) was done mechanically, not by
eye alone: the full unified diff (`-U0`) for the 7 touched files was captured, and a small script
paired every `-`/`+` line, substituted `StoreIds.RejectionStore`→`6` and
`StoreIds.ReworkStore`→`7` back into the `+` line, and asserted byte-equality with the `-` line.
**Result: 55/55 pairs value-equal, 0 mismatches.**

**A mistake made and fully reverted before committing, recorded honestly.** The first
replacement pass matched `AddOrUpdateStockAsync(…, 6|7,` anywhere in each file's raw text and
produced 58 replacements, not 55 — 3 of them inside `//`-commented-out calls (`SubConSCNService.cs:730`,
`ProductionSCNCompService.cs:622,973`, all three already correctly classified `COMMENTED OUT` by
`INV-059` and meant to be left untouched). All 7 touched files were reverted with
`git checkout --`, the script was fixed to mask full-line comments before matching (preserving
character offsets so the same regex still finds real calls), and the corrected run produced
exactly 55 replacements on the first attempt, independently matching `INV-059`'s 24/31 split.

## Task Objective

Bring the repository to a state in which a branch-per-task workflow can actually start:
a deliberate, human-decided disposition for every one of the 37 working-tree entries; the
solution-file rename resolved; `master` protected; the branch and commit convention
recorded; and the repository's **public** visibility escalated as an urgent decision
(Q-19).

This task does **not** rotate or externalise any credential — that is M0-04 and M0-03 — but
it must not commit any file that carries one. Secret-bearing files are explicitly deferred
to those tasks and remain uncommitted at the end of M0-00.

## Why This Task Exists

**Confirmed (verified 2026-08-12 in this repository).**

1. `git log --oneline --all` returns exactly one commit: `c12c5b2 Add project files.`
   There is no history to branch from, revert to, or bisect.
2. `git status --porcelain` returns **37** entries: 26 modified, 1 deleted, 10 untracked
   path entries. Expanded with `--untracked-files=all` the untracked set is **95 files**.
3. The tracked solution file `Bhargavi V.SMART ERP - 2025.sln` is deleted in the working
   tree (`git ls-tree -r HEAD --name-only` confirms it is the only `.sln` in `HEAD`), while
   a differently-named replacement `NexGen-ERP---2025-master.sln` is untracked. Every
   command in [KB-083](../prompt-template.md) that names the solution therefore names a file
   that does not exist in `HEAD`.
4. `git ls-remote https://github.com/ErpStore/NexERP_B.git` succeeds **without
   authentication** ⇒ the GitHub repository is **public** (INV-029, via
   [KB-080 §6](../README.md#findings-from-this-planning-pass-that-changed-m0)).
5. Live database credentials are hardcoded in committed C#:
   `V.SMART/V.SMART.Shared/Data/MigrationData/ApplicationDbContextFactory.cs:13-14` holds a
   `sa` connection string and a commented production connection string to
   `154.61.76.112,1533`. This is R-01 ([KB-060 §R-01](../../risks/technical-debt-register.md)),
   escalated by fact 4 from *committed* to *published*.

[KB-080 §19](../README.md#19-git-strategy) states the precondition plainly: no
branch-per-task workflow starts until the working tree is resolved. Every later M0/M2 task
assumes `migration/<TASK-ID>-<slug>` branches cut from a clean `master`.

Risks served: **R-01**, **R-02** (containment only — this task prevents *further* exposure),
and the [KB-080 §7](../README.md#7--m0--stabilise) M0 critical path
`M0-00 → M0-08 → M0-07 → M0-12-01 → M0-13 → M0-11 → G0`.

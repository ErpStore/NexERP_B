# M2-A11 — Re-specify M2-A05 for Angular

## Objective

Re-specify [`M2-A05`](M2-A05.md) — "Tenant resolution for a cross-origin SPA + real CORS" —
against [`ADR-007`](../../decisions/ADR-007-angular-stack.md) and the current, real state of
`frontend/nexgen-web/`, so it is safe to dispatch. This task creates no application code; it
is documentation only.

## Why this task exists

A select-only pass on 2026-08-27 (after `M2-C03` merged) tried to dispatch `M2-D01`, found it
genuinely blocked on `M2-A05`, then checked `M2-A05` itself as the fallback candidate.
`M2-A05` mechanically clears the five-part "can actually be done" test, but its task file was
never re-specified for Angular the way the `M2-C`/`M2-D` tree was by `M2-C12-01`…`-05`:
`M2-A05` sits in the `M2-A` milestone, entirely outside `M2-C12`'s declared scope ("the
superseded **M2-C / M2-D** task tree"), so it was never swept.

Unlike the `M2-C`/`M2-D` files, `M2-A05` never carried a `⛔ STOP — this specification is
superseded` banner in the first place — nothing gated it on `M2-C00`, so nothing flagged it as
stale when the stack switched on 2026-08-20. It said "the React app" and carried a whole
_React Changes_ section, silently, until this pass actually tried to read it end to end.

Three concrete, verified divergences made this more than a word-swap:

1. **The claim "`M2-C02` implements the tenant picker" is simply false.** `M2-C02` is
   `Completed` and merged; its login request is `{ username, password }` only, and both
   `login.component.ts` and `auth.service.ts` carry doc comments stating explicitly that
   tenant resolution stays deferred to `M2-A05`. This is not a gap `M2-A05` discovers — it is
   a documented, deliberate deferral `M2-A05` is the target of, and the original text
   described work that was never built.
2. **The route prefix changed.** `M2-B01` (`/api/v1` versioning) landed after this file's
   `2026-08-12 last_verified`. Every route in the file read `/api/auth/…`; the real routes
   are `/api/v1/auth/…` (`AuthController.cs:13`).
3. **The error-shape prerequisite already happened.** `M2-A06` (`ProblemDetails`) landed too.
   The file's own Dependencies table called it a "Soft" dependency still pending; the
   unresolved-tenant response is already `application/problem+json` via a
   `TenantUnresolvedProblem` helper, and the Angular side already has a `'tenant-unresolved'`
   `LoginFailure` case wired and waiting for it.

Re-specifying now, rather than leaving it for whoever eventually picks up `M2-A05`, means the
next session that reaches it inherits an accurate contract instead of inheriting the staleness
and having to re-derive all three findings under time pressure.

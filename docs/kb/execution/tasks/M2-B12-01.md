**R-12 cannot be fixed from its own description.** The register entry
([KB-060](../../risks/technical-debt-register.md)) is one paragraph, and re-verification on
2026-08-12 showed **two of its four factual claims are wrong**:

| R-12 says | Reality (Confirmed, 2026-08-12) |
|---|---|
| "no lock, no `UPDLOCK`" | **37 of 38** raw-SQL numbering statements carry `WITH (UPDLOCK, ROWLOCK)` |
| "~20 repositories" | **36** repository files, **38** raw-SQL sites, plus 7 lock-free LINQ sites and 4 allocation-table read-modify-write methods |
| "no serializable transaction" | Correct — `HOLDLOCK`/`IsolationLevel`/`Serializable`/`sp_getapplock` return **zero** matches across `V.SMART/` |
| "no DB sequence" | Correct |

An engineer told to "replace the ~20 `SELECT TOP 1` calls" would miss the
`CommonService.GenerateAutoRunningNoAsync` allocator, which is where the *worst* race
actually lives, and would be surprised to find `UPDLOCK` already present in the code they
were told had none. **That is the failure this task prevents.**

The correction matters in a specific way. `UPDLOCK, ROWLOCK` **does not** make these reads
safe: it takes a row-level update lock, not a range lock, so it cannot block the *insert*
that a competing session is about to perform; and outside an explicit transaction it is
released when the statement completes. The hint is close to decorative — and it has already
misled a reader, as the comment
`// Safely fetch the latest QuoteNo with locking to prevent concurrency issues`
(`V.SMART/V.SMART.Shared/Repository/OutSourcingRepository/DebitNote_Repository/DebitNoteRepository.cs:32`)
shows. **The inventory must say this in plain words** so that no reviewer of
[M2-B12-03](M2-B12-03.md) argues the code is already protected.

**R-12 stays `Inferred (high confidence)` at the end of this task.** Reading code proves a
race is *possible*; it does not prove one has *occurred*. Only
[M2-B12-02](M2-B12-02.md)'s duplicate census can upgrade the classification. Do not upgrade
it here. Do not downgrade it either.

## Investigation Requirements

**This task *is* INV-012.** There is no prior investigation to reuse for its substance —
INV-012 is `Scheduled` and has never been run. INV-002 and INV-011 supply context only.

The investigation has **four** deliverables. All four are required; a session that produces
three has not completed the task.

### 1. The call-site inventory

Every place in `V.SMART/**` that derives, allocates or records a document number. Group by
**mechanism**, not by module, because the mechanism is what determines the remedy. The three
mechanisms found on 2026-08-12 (Confirmed — reproduce and reconcile, do not copy):

- **A — raw-SQL last-number read.** `FromSqlRaw` /
  `Database.SqlQuery<string>` with `SELECT TOP 1 … ORDER BY TRY_CAST(<col> AS INT) DESC`,
  then `+1` in C#. 38 sites, 36 files.
- **B — lock-free LINQ last-number read.** `OrderByDescending(...).Select(...).FirstOrDefaultAsync()`,
  then `+1` or a regex increment in C#.
- **C — allocation-table read-modify-write.** Read a row from `DcRunningNumbers` /
  `InvoiceAutoRunningNumbers`, mutate `LastNumber`, `SaveAsync()`.

For each site record: file, line range, method name, the table read, the number column, the
**scope columns** in the `WHERE` (this is what M2-B12-02 needs), whether a lock hint is
present, and whether the call sits inside an explicit transaction.

### 2. The format catalogue

For every document series: the exact user-visible string, where it is assembled, and the
suffix rule. Include worked examples. This is the artefact that
[M2-B12-03](M2-B12-03.md)'s characterisation tests are written from, and it is the reason
this task is 2 days rather than half a day.

### 3. The financial-year rule, including its duplicate

`V.SMART/V.SMART.Shared/Services/FinancialYearHelper.cs:11-17` is 19 lines total and
returns `"/{year}-{yy}"` from `date.Month >= 4 ? date.Year : date.Year - 1`. **There is a
second, independent implementation** at
`V.SMART/V.SMART.Shared/BusinessLayer/BusinessService/CommonService.cs:1849-1851`, which
writes the same rule as `now.Month > 3` and formats as `"{yy}-{yy}"` — *a different string
shape*. Record both, state whether they agree on the boundary (they do — `Month >= 4` and
`Month > 3` are the same predicate over integers), and record that their **output formats
differ**. Then find out which one actually reaches a stored `Suffix` value. That is a real
question this task must answer, not restate.

### 4. The `BookTypeDc` series-sharing rules

`CommonService.GenerateAutoRunningNoAsync` (`:1845-1963`) branches on a
`Company.BookTypeDc` byte to decide whether MFGDC / LABOURDCOUTGOING / SUBCONDCOUT draw from
separate, partially shared or fully shared number series (`:1883-1907`), with a further
`bookTypeDc <= 0` fallback at `:1928-1944`. Enumerate all branches as business rules and
register them in [KB-030](../../business-rules/business-rule-inventory.md) with fresh
`BR-DOC-nnn` ids. Any remedy must reproduce every branch.

**Record negative results.** "Grepped `V.SMART/` for `sp_getapplock` / `HOLDLOCK` /
`IsolationLevel` / `Serializable` — zero matches" is one of the most load-bearing findings
in this task, because it is what rules out "it is already handled somewhere else".

WHY IT MATTERS NOW
Blazor Server's low concurrency is the ONLY thing currently
masking this race. That is a property of the HOST, not of the
code. An HTTP API raises concurrency well above what Blazor
Server produces: a React client can fire concurrent POSTs, a
retried request after a timeout produces a second create, and a
load test produces hundreds. The numbering fix must therefore
land BEFORE the first document-creating endpoint exists. Today
V.SMART.Api has no such endpoint, which is exactly why this work
is cheap now and expensive later.

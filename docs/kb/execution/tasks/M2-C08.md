## Task Objective

Build the `DocumentEditor` **shell** — the single component that all ~65 React document
editor screens are configurations of, per
[ADR-003 non-negotiable rule 6](../../decisions/ADR-003-react-stack.md#non-negotiable-rules):
*"One `DocumentEditor` component configured 65 ways, not 65 bespoke editors."*

The shell owns four things and nothing else:

1. **Layout** — page header, header form, `LineItemGrid`, totals panel, command bar,
   attachments/terms/audit region, dirty-state guard (M2-C08-01).
2. **Totals wiring** — display of totals that the **server** computed, with an optional
   provisional client echo that the server's response always overwrites (M2-C08-02).
3. **Workflow commands** — one `POST /api/v1/{resource}/{id}/{verb}` per user action, never a
   client-orchestrated sequence (M2-C08-03).
4. A configuration contract that a feature module fills in.

## Why This Task Exists

- **It is the single highest-leverage decision in the frontend.**
  [KB-050](../../frontend-new/react-architecture.md#document-editor-pattern-the-core-abstraction)
  states it converts *"~65 screens of 3,000–6,500 LOC each into one component plus 65
  configs."*
- **It gates M3.** [KB-080 §9](../README.md#critical-path): M2-C07 and M2-C08 are not on the
  M2 critical path but are on M3's, and *"must complete inside M2 or M3-5 stalls."*
- **It is where the two most consequential correctness constraints in the project meet the
  UI**: server-authoritative totals (BR-CALC-001) and server-orchestrated workflow (ADR-002).
  Both are structural properties of the shell, which is why they are children rather than
  later hardening.

**Scope boundary, stated once and enforced in every child:** M2-C08 builds the **shell** and
the **command pattern**. It does **not** migrate the Sales Order module. Sales Order is wave
**M3-5**, and [KB-080 §10](../README.md#10-module-migration-task-pattern) requires its
business-logic extraction (`M3-5-03`) to complete and be verified (`M3-5-04`) *before* its
React screens (`M3-5-08`) are built. `MfgPOUpsert.razor` and `MfgPoService.cs` are
**read-only reference** throughout M2.

[KB-080 §9 Risks](../README.md#risks-1) already accepts the consequence:
*"`DocumentEditor` under-specified because no document module has migrated yet → Accept:
build the shell in M2, harden it in M3-5 against a real document."* That acceptance is what
makes a generic shell the correct deliverable here, and a Sales Order screen the wrong one.

## Combined Acceptance Criteria

- [ ] `frontend/nexgen-web/src/shared/components/DocumentEditor/` exists and exports one
      generic `DocumentEditor<THeader, TLine>` driven by a `DocumentEditorConfig` object.
- [ ] The layout matches [KB-050's document-editor pattern](../../frontend-new/react-architecture.md#document-editor-pattern-the-core-abstraction):
      page header with status badge and actions, header form, `LineItemGrid`, read-only totals
      panel, attachments/terms/remarks/audit region, sticky command bar.
- [ ] The shell embeds `LineItemGrid` (M2-C07) and `RecordPickerDialog` (M2-C06) rather than
      re-implementing either.
- [ ] Navigation away from a dirty editor is blocked via React Router's `useBlocker`,
      replacing `V.SMART/V.SMART.Shared/Components/UnsavedChangesModal.razor`.
- [ ] **Totals are never computed by React.** The totals panel is read-only, its values come
      from the server, and the server's response overwrites any provisional client value
      before save. Enforced by test, not by convention.
- [ ] `grep` over the `DocumentEditor` directory finds no tax rate, no rounding rule, no
      proportional-allocation arithmetic, and no re-implementation of any step of
      `CalculationService.UpdateTotalsAsync`
      (`V.SMART/V.SMART.Shared/Services/CalculationService.cs:12-114`).
- [ ] Every workflow action (cancel, short-close, approve, reject, release, post) issues
      **exactly one** `POST /api/v1/{resource}/{id}/{verb}` and renders the outcome. No action
      is composed client-side from two or more calls.
- [ ] A 409 business-rule refusal renders the server's message **verbatim** — for example
      `"Cannot delete this Sales Order as a Sales DC transaction exists."`
      (`V.SMART/V.SMART.Shared/BusinessLayer/BusinessService/SalesService/MfgPoService.cs:488`,
      BR-SO-001) — with no rewriting, prefixing or genericising.
- [ ] Commands that require a reason collect it before dispatch and send it with the single
      request (BR-SO-003 pattern).
- [ ] The shell is generic: no Sales Order, purchase, invoice or any other module-specific
      field name, endpoint, status or rule appears in the component directory.
- [ ] No file under `V.SMART/**` is modified: `git diff --stat -- V.SMART/` is empty.
- [ ] Accessibility: full keyboard operation, focus never lost across a save or a command,
      status and totals announced via `aria-live`, no colour-only status encoding, axe clean.
- [ ] `npm run lint`, `npm run test`, `npm run build` (established by M2-C01) all pass.

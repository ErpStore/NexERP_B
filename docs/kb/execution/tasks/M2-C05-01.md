# M2-C05-01 — Server-paged table core

> **Re-specified for Angular on 2026-08-22 by [`M2-C12-03`](M2-C12-03.md).** The ⛔ STOP banner
> that stood here is removed **in the same change that removed the stack-specific instructions it
> guarded**: this file no longer specifies the ADR-003 stack.
> [`ADR-007`](../../decisions/ADR-007-angular-stack.md) is the governing stack decision —
> **Angular 22.x + PrimeNG**, and specifically *"PrimeNG Table; `LineItemGrid` re-evaluated"*
> (`ADR-007-angular-stack.md:98`) with the reasoning at `:151-158` — and
> [KB-050](../../frontend-new/react-architecture.md), rewritten for Angular by `M2-C00`, is the
> structure this component is built into.
>
> **The specification this replaces is not deleted from the record.** Its *intent* survives
> unchanged and is what this file still states: one generic, server-paged, virtualised,
> keyboard-complete grid; query state that round-trips through the URL; `aria-rowcount` reflecting
> the server total; a column model mirroring `GridColumn.cs`; and typed seams for the two sibling
> tasks. What changed is the *how*, and one thing changed more than the others: the replaced
> specification told the implementer to **own** the table by building on a headless library.
> ADR-007 reverses that deliberately (`ADR-007-angular-stack.md:151-158`) — this task now **wraps**
> PrimeNG's `p-table` in `lazy` mode. Owning grid internals is the maintenance cost ADR-007
> declined on the owner's behalf. Everything else re-derives mechanically: signals instead of
> hooks, an injectable service instead of a store, `HttpClient` instead of a query library,
> `ActivatedRoute` query params instead of a router hook, component styles instead of CSS Modules.
> The `file:line` evidence about the existing Blazor implementation was never a framework decision
> and comes through byte-identical.

## Objective

Build the core of `DataGridComponent<TRow>`: a generic, **server-paged** list grid wrapping
PrimeNG's `p-table`, together with the query-state service that binds it to a paged API endpoint
and lets the hosting route mirror that state into the URL.

Scope of *this* child:

- Standalone `DataGridComponent<TRow>` + a typed column-definition model.
- `DataGridQueryState` — page / pageSize / sort / filter state held in signals, with an
  `ActivatedRoute`/`Router` binding so a list route's URL is the single source of truth, and a
  detached mode for hosts that must **not** write the URL (M2-C06's dialog).
- Row virtualisation via `p-table`'s `[virtualScroll]`, engaged above the row threshold.
- Sticky header, left/right frozen columns, column resizing, density toggle
  (comfortable 36 px / compact 30 px per [KB-051](../../frontend-new/design-system.md#principles)).
- Row selection (single, multi, select-all-on-page) and an inline row-actions slot.
- The full ARIA `grid` keyboard model.

Explicitly **not** in this child: column preference persistence (M2-C05-02), the
empty/loading/error triad and export (M2-C05-03).

## Scope

Everything under `frontend/nexgen-web/src/app/shared/components/data-grid/`, plus the KB updates

## Why This Task Exists

Three reasons, in order of weight:

1. **Critical path.** [KB-080 §9 Critical Path](../README.md#critical-path) runs
   `M2-C01 → M2-C04-01 → M2-C04-02 → M2-C05-01 → M2-C05-03 → M2-D01`. Nothing on the M2
   vertical slice ships without it.
2. **Fan-out.** M2-C06 (`RecordPickerDialog`), M2-C07 (`LineItemGrid`) and M2-C09
   (`ReportPage`) all declare `M2-C05-01` as a hard dependency
   ([KB-080 §9](../README.md#critical-path)). It is the single highest-fan-out frontend task
   in M2.
3. **Risk R-22.** [KB-060 R-22](../../risks/technical-debt-register.md) records two
   overlapping design systems in the existing UI. Replacing 93 `<QuickGrid>`-and-Bootstrap
   list screens with one owned component over one component library is how that risk is retired
   for list screens.

It also protects a stated performance target that the current architecture cannot meet:
[KB-050](../../frontend-new/react-architecture.md#performance-targets) requires a
10,000-row grid to scroll virtualised at 60 fps. `<QuickGrid Items="vm.AsQueryable()">` as
used today (e.g. `V.SMART/V.SMART.Shared/Pages/CashFlow_Pages/Payments_Pages/PaymentList.razor:134`)
materialises the collection in the Blazor circuit first.

## Target Result

A generic, reusable standalone component used like this (illustrative — the final input names
are this task's design decision, but the capabilities are not optional):

```html
<app-data-grid
  [columns]="customerColumns"
  [state]="grid.state()"
  [rows]="grid.rows()"
  [totalCount]="grid.totalCount()"
  [loading]="grid.loading()"
  [refetching]="grid.refetching()"
  [error]="grid.error()"
  [density]="'comfortable'"
  [getRowId]="byCustId"
  [selection]="{ mode: 'multiple', selected: selected() }"
  (selectionChange)="selected.set($event)"
  (stateChange)="grid.apply($event)"
  (rowActivate)="open($event)">
  <ng-template #rowActions let-row>…</ng-template>
</app-data-grid>
```

Behavioural target:

- **Server-driven.** `p-table` is configured `[lazy]="true"` with `[lazyLoadOnInit]="false"`;
  changing page, page size, sort or a filter emits one state change, which issues one request
  through the generated client and re-renders from the response. There is no client-side sort or
  filter over a full data set anywhere in the component.
- **URL is the state, when the host says so.** `DataGridQueryState` has two modes.
  *Route-bound* (the default for a list screen) reads and writes
  `?page=2&size=50&sort=custName:asc&custName=acme` through `ActivatedRoute.queryParamMap` and
  `Router.navigate(..., { queryParamsHandling: 'merge' })`, per
  [KB-050 §Data-fetching conventions](../../frontend-new/react-architecture.md#data-fetching-conventions);
  paste the URL into another tab and the identical grid appears, and browser back/forward work.
  *Detached* holds the same signals without touching the URL — required by M2-C06, whose dialog
  must not mutate the page behind it.
- **Previous page stays visible.** A refetch never blanks the table; the previous rows remain
  under a top progress bar ([KB-051 §State patterns](../../frontend-new/design-system.md#state-patterns)).
  With no query-cache library in the stack (ADR-007 replaced it with explicit services,
  `ADR-007-angular-stack.md:134-138`), this is the grid's own responsibility: hold the last
  successful page in a signal and swap it only when the next one resolves.
- **Virtualised above the threshold.** Rows render virtualised when the page holds ≥ 500
  rows ([KB-051 §Data display](../../frontend-new/design-system.md#data-display)); 10,000 rows
  scroll at the 60 fps target.
- **Keyboard-complete.** ARIA `grid` role; `↑ ↓ ← →` move the focused cell, `Home`/`End` go
  to first/last cell in a row, `Ctrl+Home`/`Ctrl+End` to first/last cell in the grid,
  `PageUp`/`PageDown` page the viewport, `Space` toggles row selection, `Enter` activates the
  row. Focus is never lost across a refetch.
- **Horizontal scroll is contained.** The grid scrolls inside its own container; the page
  body never scrolls sideways ([KB-051 §Data display](../../frontend-new/design-system.md#data-display)).
- **Tabular numerics.** Numeric columns are right-aligned with
  `font-variant-numeric: tabular-nums` ([KB-051 §Typography](../../frontend-new/design-system.md#typography)).
- **Extension seams present.** The component accepts (and this child leaves unimplemented but
  typed) a column-preferences seam for M2-C05-02 and state/export slots for M2-C05-03.

## Implementation Requirements

1. Read [ADR-007](../../decisions/ADR-007-angular-stack.md),
   [KB-050](../../frontend-new/react-architecture.md),
   [KB-051](../../frontend-new/design-system.md), and M2-B02's task file. Search
   `docs/kb/investigation-registry.md` before any repository investigation.
2. Confirm `frontend/nexgen-web/` exists with M2-C01's scripts. If it does not, stop and
   report Blocked — this task does not scaffold the app.
3. Run the `p-table` virtual-scroll measurement described under *Investigation Requirements*
   **first**, on a throwaway fixture. It is cheap, and it is the one thing that can invalidate
   the whole approach.
4. **Add no new runtime dependency.** `primeng` and `@angular/cdk` are already installed
   (`frontend/nexgen-web/package.json`), and PrimeNG's `Table` module is what this component
   wraps. A second grid or virtualisation library is forbidden by ADR-007's one-library rule
   (`ADR-007-angular-stack.md:170-173`) and by `eslint.config.js`'s `no-restricted-imports`.
5. Create the column model in
   `frontend/nexgen-web/src/app/shared/components/data-grid/data-grid.model.ts`, mirroring the
   ERP metadata that `V.SMART/V.SMART.Shared/ViewModels/GridColumn.cs:3-14` already establishes —
   `field`, `title`, `align`, `width`, `isDate`, `numeric`, `frozen`, `hideable`, `exportable`,
   `defaultVisible`, `priority`. Keep the vocabulary aligned so M2-C05-02 can round-trip
   persisted preferences without a translation table that drifts.
6. Implement `DataGridQueryState` in
   `frontend/nexgen-web/src/app/shared/components/data-grid/data-grid-query-state.ts`:
   - Owns `{ page, pageSize, sort, filters }` as signals, exposed read-only via `asReadonly()`.
   - Route-bound mode reads and writes them through `ActivatedRoute` / `Router`, so the URL is
     the single source of truth; detached mode does not.
   - Serialises to M2-B02's query-parameter contract via **one** adapter function; that
     function is the only place that knows the wire format.
   - Debounces free-text filter changes (300 ms, RxJS `debounceTime` — ADR-007 keeps RxJS for
     event streams, `ADR-007-angular-stack.md:140-142`) and resets `page` to 1 on any filter or
     sort change.
7. Implement the data binding in a typed service pattern, per
   [KB-050 §Data-fetching conventions](../../frontend-new/react-architecture.md#data-fetching-conventions):
   `HttpClient` through the generated client, result held in a signal, an explicit `refresh()`,
   and the previous page retained until the next resolves. No cache-key machinery — there is no
   cache to invalidate.
8. Implement `data-grid.component.ts` / `.html` over `p-table` with `[lazy]="true"`. Assert in a
   test that no sorting or filtering happens locally — a regression to client-side paging is the
   single most likely silent failure of this component.
9. Enable `[virtualScroll]` with a fixed `[virtualScrollItemSize]` matching the active density,
   engaged when the page holds ≥ 500 rows. Keep the header outside the virtual window so it
   stays sticky.
10. Implement frozen columns (left/right), column resizing (pointer, plus keyboard via
    `←`/`→` on a focused resize handle), and the density toggle mapping to the 36 px /
    30 px row heights from [KB-051](../../frontend-new/design-system.md#principles).
11. Implement selection: `none` / `single` / `multiple`; a header checkbox that selects the
    current page only, with an explicit indeterminate state; selection keyed by `getRowId`
    so it survives a refetch. Selection state is owned by the caller (a two-way binding), not
    the grid.
12. Implement the ARIA grid keyboard model listed in *Target Result*, in
    `grid-keyboard-navigation.ts`. Roving `tabindex`; exactly one tab stop for the whole
    grid; focus restored to the same cell coordinates after a refetch. PrimeNG's own keyboard
    handling is a starting point, not the specification — verify each key against the list and
    add what is missing rather than assuming coverage.
13. Style with the component's own `styleUrl`, referencing design tokens only
    (`data-grid.component.css`). No raw hex values, no Bootstrap classes, no `!important`, and
    no global PrimeNG theme override — theming is M2-C04-01's.
14. Add the extension seams: an optional two-way `columnVisibility` input (wired for real by
    M2-C05-02), and optional `empty` / `error` / `toolbar` `ng-template` slots (filled by
    M2-C05-03). Type them now, implement them there, and mark them in code comments with the
    owning task id.
15. Build a test-only fixture with a stubbed paged endpoint exercising 0, 1, 25 and 10,000 rows.
    Stub the HTTP layer with `provideHttpClientTesting` / `HttpTestingController`; **do not**
    add a request-interception library — Angular ships one.
16. Write the tests listed under *Testing Requirements*.
17. Run the verification commands. Review the full `git diff`. Update the documentation and
    the investigation registry as specified.

| **Empty state** | Seam only in this child (`empty` template). The default placeholder must still be accessible (`role="status"`), never an empty `<tbody>`. |
| **Error state** | Seam only in this child (`error` template). This child must propagate the normalised `ProblemDetails` object untouched — it must not stringify or genericise the server message. |
| **Accessibility** | ARIA `grid` pattern; roving `tabindex` with one grid-level tab stop; `aria-rowcount`/`aria-colcount` reflecting the **server** total, not the page; `aria-sort` on sortable headers; visible 2 px focus ring with 2 px offset; header checkbox labelled; `aria-live="polite"` announcement of page and result-count changes; usable at 200% zoom. |
| **Responsive behaviour** | ≥1440: all columns. 1024–1439: grid keeps horizontal scroll inside its own container. 768–1023: low-priority columns (`priority: 'low'` in the column model) drop out. <768: read-only rendering; editing affordances are not this component's concern ([KB-051 §Responsive behaviour](../../frontend-new/design-system.md#responsive-behaviour)). |

## Business Rules

**None.** `DataGrid` is new code, so "preserved unchanged" would be false. What is new is
*table presentation and query-state plumbing*: paging, sorting, filtering, virtualisation,
selection, keyboard navigation.

**No ERP business rule is implemented client-side by this task.** No calculation, no
validation of domain values, no status transition, no permission decision, no stock or money
arithmetic. The grid receives rows and column metadata and renders them. Every domain
decision stays behind the API, per migration principles 3 and 4 in
[KB-080 §3](../README.md#3-migration-principles) and ADR-007's carried-over rule
*"server-authoritative everything"* (`ADR-007-angular-stack.md:162-164`).

Concretely forbidden in this component: computing a totals row from the visible page,
formatting money by multiplying floats, deciding whether a row is editable, or filtering
rows out because of a domain condition.

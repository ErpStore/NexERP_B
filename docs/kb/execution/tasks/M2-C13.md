## Objective

Bring the initial bundle back under Angular's **600 kB** warning budget by deferring the
confirm-dialog host, **without** losing a confirmation request issued before that host has
mounted.

## Why this task exists, and an honest note on its urgency

[R-69](../../risks/technical-debt-register.md) records the measurement: the initial bundle went
from **446.36 kB raw / 106.63 kB gzip** to **711.75 kB raw / 158.28 kB gzip** when `M2-C04-03`
added the single `<p-toast>` and `<app-confirm-dialog>` hosts to `app.component.html`. They are
eager by necessity — a screen cannot place its own host without risking a duplicate message — and
they drag `p-dialog`, `p-confirmdialog`, `app-form-field` and `app-textarea` into the initial
chunk with them.

`npm run build` **exits 0**: 600 kB is the *warning* budget. The **error** budget is 800 kB, so
there is **88 kB of headroom before the build fails**, and no gate will catch the crossing —
a warning does not fail CI.

> **Correction to R-69's own framing, and to the close-out note on `M2-C04-03`.** Both say the
> app shell `M2-C03` "lands next" and will consume the remaining headroom. **It cannot.**
> `M2-C03` `depends_on: [M2-C02, M2-C04-01]`, and `M2-C02` needs `M2-A04`, which is Hard-blocked
> on **`M0-04`** (credential rotation, deferred by the owner). `M2-C03` is therefore transitively
> blocked behind `M0-04` and is not imminent. **This task is not a race.** It is worth doing
> because 88 kB is a thin margin, the fix is already understood, and this is currently the only
> executable work in the repository — not because a deadline is approaching. Fix R-69's wording
> as part of this task.

## The trap that must not be re-sprung

R-69 measured it, and it is the single most valuable fact here: importing the two hosts **from
their own files** rather than from the `shared/components` **barrel** is what keeps the bundle at
711 kB instead of **1.31 MB — a build that fails outright**, because the barrel drags every form
control and `decimal.js` into the initial chunk.

**Do not add a barrel import to `app.component.ts`, and do not "tidy" the existing direct imports
into one.** If the bundle jumps by ~600 kB, this is why.

## The correctness constraint — the reason this is not a one-line change

`ConfirmDialogService.confirm()` (`confirm-dialog.service.ts:66-83`) calls
`this.primeng.confirm({...})`, which pushes onto PrimeNG's `requireConfirmation$`. That is a plain
**`Subject`**, not a `ReplaySubject` or `BehaviorSubject`: **an emission with no subscriber is
dropped, silently and permanently.** `app-confirm-dialog` is the subscriber, and it only
subscribes once mounted.

So deferring the host creates a real defect unless the service handles it: the first
`confirm()` call — the one that *triggers* the mount — would emit into nothing, and its
`Promise<ConfirmResult>` would never resolve. The caller awaits forever, with no error.

**The service must hold the request until the host is mounted and subscribed, then emit.** How is
the implementer's choice; what matters is that the promise resolves correctly on the *first* call.

## Scope

1. Defer the `<app-confirm-dialog>` host so `p-confirmdialog`, `app-form-field` and `app-textarea`
   leave the initial chunk — `@defer` with an appropriate trigger, or a lazy dynamic import.
2. Make `ConfirmDialogService` correct across the mount boundary, per the constraint above.
3. Leave the `<p-toast>` host alone unless deferring it is *also* proven safe and needed to reach
   budget — toasts are fire-and-forget and have the same lost-emission hazard, with no promise to
   strand. If it is deferred, the same first-call proof is required.
4. Correct R-69's and `M2-C04-03`'s "`M2-C03` lands next" claim (see above).

## Out of Scope

- **Raising the budget in `angular.json`.** Moving the number is not fixing the size. If the
  implementer concludes the budget itself is wrong, say so with evidence and stop — that is an
  owner decision.
- Any change to what the dialog *does*: its keyboard model, focus contract (`M2-C04-03` asserted
  it, and INV-006 records the `p-confirmdialog` focus defect), `reasonRequired` behaviour, or the
  `ConfirmRequest`/`ConfirmResult` contract.
- The **single-host invariant**. One toast host, one confirm host, application-wide. A second host
  means a message appears twice or in the wrong stacking context.
- Anything outside `frontend/` and `docs/kb/`.

## Acceptance Criteria

1. **`npm run build` emits no `bundle initial exceeded maximum budget` warning.** Quote the actual
   build output. If budget cannot be reached, criterion 6 applies instead — do not silently miss it.
2. **Initial raw total is below 600 kB**, reported as before → after against the recorded
   **711.75 kB** baseline.
3. **A test proves the first-call case**: `ConfirmDialogService.confirm()` invoked when the host
   has *never* mounted resolves its promise with the correct `ConfirmResult`. This is the defect
   the deferral would otherwise introduce; a test that only exercises an already-mounted host does
   **not** satisfy this.
4. Cancellation paths still resolve `{ confirmed: false, reason: null }` — Cancel, `Esc`, backdrop
   and close icon alike.
5. `reasonRequired` still refuses confirmation without a reason, and a supplied reason still
   arrives trimmed via `captureReason`.
6. **No barrel import** in `app.component.ts`: `grep -n "shared/components'" src/app/app.component.ts`
   returns nothing. If the bundle rises by roughly 600 kB, this criterion was violated.
7. All existing gates hold on the merged result: `typecheck` exit 0 · `lint` clean ·
   `format:check` clean · `test:ci` **≥ 304 passed** with **zero** failures · `build` exit 0.
8. Zero raw hex or `rgb()` in any stylesheet touched; tokens via `var(--…)` only — the rule
   `M2-C04-01` established and `M2-C04-02`/`-03` have kept.
9. Diff confined to `frontend/` and `docs/kb/`, proved by
   `git diff --name-only master...HEAD | grep -vE '^(frontend/|docs/kb/)'` returning empty.
10. **R-69 updated with the measured after-figure** and marked resolved or reduced accordingly;
    its "`M2-C03` lands next" claim corrected.

## Testing Requirements

- The first-call test of criterion 3 is the one that matters. Write it so it **fails** against the
  deferred host without the service fix — state in the Execution Record that this was confirmed,
  not assumed. A test that passes either way proves nothing.
- Re-run the full frontend suite; **304 passing is the floor**, not the target.
- Report the build's own budget line verbatim, before and after.

## Task Objective

Bring the DDL of every stored procedure the application executes into source control, add a
repeatable deployment step for it, and prove by runbook that a fresh, empty SQL Server can
be brought to a working tenant database **from source control alone**.

The end state is a `db/stored-procedures/` directory (**TO BE CREATED**) containing one
`.sql` file per procedure, an ordered deployment script, and a rebuild runbook, plus a
reconciliation document that records exactly which procedure names the application
references and where.

## Why This Task Exists

**R-04 (Critical, Confirmed)** — [`docs/kb/risks/technical-debt-register.md`](../../risks/technical-debt-register.md):
94 distinct `Sp_*` names are referenced from C#/Razor, and only 13 `.sql` files exist, in
`Existing Store Procedures/StoredProcedures/`. A tenant database therefore cannot be
rebuilt from the repository, and every report and every printed statutory document breaks in
a fresh environment.

Three separate documents make this the binding constraint on gate **G0**:

- [KB-080 §7](../README.md#7--m0--stabilise) — G0's first exit criterion is literally
  "a fresh, empty SQL Server can be brought to a working tenant database **from source
  control alone** (EF migrations + all 94 procedures) and the app runs against it", and the
  M0 risk table names "No live-database access → M0-01 stalls, blocking G0" as the first
  risk, to be escalated on day 1.
- [ADR-005](../../decisions/ADR-005-reporting-and-printing.md) — the whole reporting and
  printing strategy (keep FastReport + the stored procedures, expose them over HTTP) carries
  a **mandatory prerequisite**: "R-04 must be fixed first … Until then, reporting cannot be
  rebuilt in a fresh environment at all." M2-B08 and M2-C09 depend on this task.
- [KB-060 priority sequence](../../risks/technical-debt-register.md#priority-sequence) —
  R-04 is a week-1 item, "do this before any other work".

**Correction to the R-04 headline number, established while planning this task
(Confirmed).** The gap is **82**, not 81. `Existing Store Procedures/StoredProcedures/Sp_Print_PurchaseOrder.sql`
declares `[dbo].[Sp_Print_PurchaseOrder]`, a name that appears **nowhere** in C# or Razor;
the code calls `Sp_Print_PurchasePo`, which has no DDL. So only **12** of the 13 scripted
files correspond to a referenced name. M0-01-01 exists to establish this reconciliation
rigorously rather than by assertion, and to surface any further mismatches of the same kind.

## Rollup Gate Contribution

This task, together with [M0-02](M0-02.md), is solely responsible for **G0 exit criterion 1**:

> A fresh, empty SQL Server can be brought to a working tenant database **from source
> control alone** (EF migrations + all 94 procedures) and the app runs against it.

It contributes nothing to the other six G0 criteria, and no other M0 task contributes to
this one. It is on the G0 critical path in its own right:

```
M0-01-01 → M0-01-02 → M0-01-03 ──► G0
                └────► M0-02 ─────► Q-14 answered or explicitly deferred
```

Two caveats that the gate reviewer must hold:

1. **A partial capture does not pass the gate.** "Most reports work" is not the criterion;
   the criterion is that the environment is reconstructible. A single missing procedure
   fails it, because the failure surfaces at report-run time in production, not at build time.
2. **G0 criterion 1 also depends on Q-02** (*how are EF migrations rolled out per tenant?* —
   [open-questions.md](../../open-questions.md)), which is **Unknown** and owned by ops.
   Confirmed: there is **no** `Migrate()` or `MigrateAsync()` call anywhere in `V.SMART/`,
   so nothing in the application applies migrations at startup. M0-01-03's runbook must
   state the migration step it actually used and flag Q-02 explicitly rather than implying
   the question is closed. This task can satisfy the *procedure* half of criterion 1 without
   the *migration* half being answered; the gate reviewer must not treat the two as one.

Blocked downstream of this task: [ADR-005](../../decisions/ADR-005-reporting-and-printing.md)
in full, and therefore M2-B08 (report + print endpoints), M2-C09 (`ReportPage` framework),
M3-6 and M4-11 (the ~40 report screens).

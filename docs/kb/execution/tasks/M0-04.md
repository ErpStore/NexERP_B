## Task Objective

Rotate every credential that has been published, and record that it was done.

**This task is largely outside the repository.** Rotating a SQL login on a production
host, re-keying a GST e-Invoice gateway account, and deciding whether a public GitHub
repository should stay public are all operations performed by a human with production
access and organisational authority.

What an AI session can and must deliver is therefore:

1. **The rotation runbook** — an ordered, executable procedure a human follows.
2. **The complete inventory** — every location each credential is consumed from, including
   the ones that are *not* files.
3. **The verification checklist** — objective, per-credential checks a human ticks off, so
   "rotated" is a fact and not a claim.
4. **Q-19 raised and recorded** as the very first action.

**Start this task immediately, in parallel with M0-00.** It has no prerequisites and it
blocks nothing until M0-05 ([KB-080 §7 Parallel Work](../README.md#parallel-work)).

## Existing Behavior to Preserve

Rotation must not take the ERP down for longer than the agreed window. The behaviours that
constrain the procedure:

- **Every tenant database is reached through a connection string stored in the master
  database.** `TenantProvider.GetCurrentTenant()` returns a `TenantInfo`
  (`V.SMART/V.SMART.Shared/Data/TenantInfo.cs:3-9`, fields `Id, Name, Hostname,
  ConnectionString`) and `TenantDbContextFactory.CreateDbContext()` builds the context from
  `.ConnectionString` with a 60-second command timeout
  (`V.SMART/V.SMART.Shared/Services/MultiCompanyService/TenantDbContextFactory.cs:14-26`).
  **Confirmed.** Therefore: rotating a SQL login used inside those stored strings requires an
  `UPDATE` against `MasterDbContext.Tenants` in the same window, or every tenant fails.
- **Tenant resolution failure is silent.** `GetCurrentTenant()` returns `null` and writes to
  `Console`; the factory then throws `NullReferenceException`
  ([KB-014 §Problems, item 4](../../architecture/multi-tenancy.md#problems-for-a-react-spa)).
  A botched rotation will therefore present as opaque 500s, not as a clear auth error. The
  runbook must say so and must include a rollback step.
- **`Jwt:Secret` rotation invalidates every issued token.** `ExpiresMinutes` is `480`
  (`V.SMART/V.SMART.Api/appsettings.json:15`), so existing tokens remain valid for up to
  8 hours after rotation unless the secret changes — and the moment it does, all of them
  fail validation at `V.SMART/V.SMART.Api/Program.cs:60-74`. With only 2 controllers and
  6 endpoints live ([KB-040](../../api/api-overview.md)) the blast radius today is small.
  **That is an argument for rotating now, before M2 puts real traffic on the API.**
- **The e-Invoice / e-Way gateway credential is a different system.** Rotating it needs the
  gateway provider's own process, and a failed rotation blocks statutory e-Invoice
  generation — a compliance impact, not just an outage. Treat it as its own change, with its
  own window and its own owner.

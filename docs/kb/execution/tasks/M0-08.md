**Completion note.** R-14's audit re-ran clean against 2,335 tracked paths (post-M0-00, up
from 2,162) — no build output, IDE state, or dependency directory is tracked. Root-level
`.gitignore` rules added and **proven to work standalone** (nested `frontend/vsmart-erp/.gitignore`
temporarily removed and `git check-ignore -v` re-run, confirming the root rules alone catch
`dist/`, `node_modules/` and `.angular/`, simulating post-M2-C11). `tools/check-no-build-output.sh`
written and **proven to fail correctly**: a throwaway file was force-added under
`frontend/vsmart-erp/dist/`, the script confirmed to exit `1` and name it, then the addition
was fully reverted and the script re-confirmed `PASS`. Before/after `git ls-files` diff shows
zero removals; no over-matching on `V.SMART.Shared.csproj` or `docs/kb/INDEX.md`. R-14
re-rated High → Medium in KB-060 (residual risk: the guard isn't wired into CI yet — that's
M0-07's job, explicitly handed off). The `dotnet build` regression-guard command in this
task's acceptance criteria **could not be run** — no .NET SDK is installed in this execution
environment. No `.cs`/`.razor` file was touched (`git status --porcelain` confirms only
`.gitignore`, `tools/`, and KB docs changed), so the regression risk that check guards against
does not apply.

## Task Objective

Close **R-14** — and correct it. Prove, mechanically and repeatably, that no build output,
IDE state or dependency directory is tracked by git; close the ignore gaps that M0-00's
commits opened; and leave behind a single command that M0-07 can run as a CI guard so the
property stays true.

## Why This Task Exists

**R-14 as written in [KB-060](../../risks/technical-debt-register.md#r-14--build-output-committed-to-the-repository)
is overstated, and this task is where that gets corrected.**

R-14 states, marked *Confirmed*: "`frontend/vsmart-erp/dist/` and
`frontend/vsmart-erp/.angular/cache/` (including `.db-lock` files) are in the tree, alongside
`.vs/` and `*.csproj.user`. **Action.** Extend `.gitignore`; remove from history."

Verified in this repository on 2026-08-12:

| Claim | Verified result |
|---|---|
| Build output is **committed** | **False.** `git ls-files` (2,162 tracked paths) contains **zero** entries matching `/dist/`, `.angular`, `node_modules/`, `^.vs/`, `csproj.user`, `/bin/` or `/obj/` |
| The paths exist on disk | **True.** `frontend/vsmart-erp/dist`, `frontend/vsmart-erp/.angular/cache`, `frontend/vsmart-erp/node_modules` and `.vs` all exist in the working tree |
| They are ignored | **True.** `git check-ignore -v` resolves them to `frontend/vsmart-erp/.gitignore:4` (`/dist`), `:10` (`/node_modules`), `:32` (`/.angular/cache`), and `.gitignore:37` (`.vs/`) |
| `*.csproj.user` | Three exist on disk (`V.SMART/V.SMART/`, `V.SMART/V.SMART.Api/`, `V.SMART/V.SMART.Web/`); none tracked; covered by `.gitignore:9` (`*.user`) |

So the accurate statement is: **build output is present in the working directory and
correctly ignored; it is not in git and never was.** R-14's "remove from history" action is
unnecessary, and acting on it — a history rewrite — would be actively harmful, colliding with
M0-05.

The task still has real work, and it is now the *right* work:

1. **The risk is live even though the debt is not.** `frontend/` is untracked in `HEAD` and
   is committed for the first time by **M0-00**. `git add frontend/` on a tree containing
   `node_modules/` and `dist/` is exactly the moment R-14 becomes true. M0-08 exists to
   verify, immediately after M0-00, that it did not.
2. **The protection is nested and fragile.** `dist`, `node_modules` and `.angular/cache` are
   ignored only by `frontend/vsmart-erp/.gitignore` — a file inside the Angular pilot, which
   [M2-C11](../README.md#m2c--react-foundation) archives. When that directory is archived or
   replaced by the React app (M2-C01), the protection leaves with it.
3. **Nothing enforces it.** There is no CI (INV-023, Confirmed: `.github/` has an *empty*
   `workflows/` directory). M0-07 needs a concrete, exit-code-returning check to run, and
   this task must supply it.
4. **The register must be corrected**, or the next reader spends a day looking for committed
   build output that does not exist — and may run a destructive history rewrite chasing it.

## Existing Behavior to Preserve

No runtime behaviour is involved — this task touches only git metadata, one new script, and
documentation.

Two things must nonetheless be preserved carefully:

1. **`frontend/vsmart-erp/.gitignore` stays as it is.** It is the Angular pilot's own file
   and `ng` tooling regenerates it. New rules go in the **root** `.gitignore`, so they
   survive M2-C11.
2. **No currently-tracked file may become ignored.** Adding a rule that shadows a tracked
   file leaves git tracking it while every tool pretends it does not exist. The
   before/after `git ls-files` comparison in step 7 is what catches this.

## Implementation Steps

1. **Confirm M0-00 landed.** `git status --porcelain` returns 0 entries or only M0-00's
   documented quarantine list. Read `docs/kb/execution/M0-00-baseline-decisions.md` to learn
   which of `frontend/`, `docs/` and `.github/` were actually committed — M0-08's audit
   depends on that outcome, and G8 was a *recommendation*, not a certainty.

2. **Capture the "before" tracked set**: `git ls-files > <scratch>/tracked-before.txt`, and
   record the count. As of 2026-08-12 it was 2,162, but M0-00 will have increased it.

3. **Audit the tracked set** for every category R-14 names, plus the ones it omits. Run the
   audit as a single grep so the result is one number:

   ```
   git ls-files | grep -E -i "(^|/)(bin|obj|dist|node_modules|\.angular|\.vs|out-tsc|bazel-out|packages)/|\.(user|suo|userosscache|rsuser)$|\.db-lock$|(^|/)TestResults/|\.vsidx$"
   ```

   Expected: no output. **If it produces output, that is the real R-14 and it must be fixed
   here** — `git rm --cached -r <path>` for each, in its own commit, with the paths listed in
   the commit body. Do **not** rewrite history to remove them; M0-05 owns history, and a
   `git rm --cached` on the tip is sufficient to stop tracking going forward.

4. **Cross-check the ignore rules resolve.** For each of `frontend/vsmart-erp/dist`,
   `frontend/vsmart-erp/.angular/cache`, `frontend/vsmart-erp/node_modules`, `.vs`,
   `V.SMART/V.SMART.Api/V.SMART.Api.csproj.user`, run `git check-ignore -v` and record which
   file and line matched. A path that is **not** ignored and **not** tracked is the gap to
   close in step 5.

5. **Extend the root `.gitignore`** with a clearly delimited block. Rules to add, each only
   if step 4 shows it is not already covered by the root file (note `.gitignore:9` `*.user`,
   `:30` `[Bb]in/`, `:31` `[Oo]bj/`, `:37` `.vs/`, `:286` `node_modules/` already exist):

   ```
   # --- M0-08: repository-level build-output guard -------------------
   # Root-level duplicates of rules that currently live only in
   # frontend/vsmart-erp/.gitignore. That file is removed by M2-C11
   # (archive the Angular pilot); these must outlive it.
   **/dist/
   **/.angular/
   **/out-tsc/
   **/coverage/
   *.db-lock
   # ------------------------------------------------------------------
   ```

   Add rules for the React app (M2-C01) only if M2-C01's scaffold already exists — it does
   not as of 2026-08-12, and inventing paths for it violates
   [KB-083](../prompt-template.md) generation rule 2. Note the requirement for M2-C01 in the
   handoff instead.

   **Do not** add `appsettings.json`, `*.config`, or any configuration file. M0-03 externalises
   secrets by *changing* configuration, not by hiding it, and ignoring a tracked config file
   would break both the Blazor host and the API.

6. **Write the guard script** at `tools/check-no-build-output.sh` (and, if the team's CI is
   Windows-hosted, a `.ps1` sibling — decide from M0-15's recommendation). It runs the step-3
   grep and exits `1` with the offending paths listed if there is any output, `0` otherwise.
   Keep it dependency-free: `git` and a shell, nothing more. It must be runnable from the
   repository root with no arguments.

7. **Prove nothing was silently un-tracked.** Capture `git ls-files > <scratch>/tracked-after.txt`
   and diff against the step-2 snapshot. The **only** permitted additions are this task's own
   new files (`tools/check-no-build-output.sh`, docs). There must be **zero removals**. If
   any tracked path disappeared, a new ignore rule shadowed it — revert that rule.

8. **Verify the ignore rules do not over-match.** Run
   `git status --porcelain --untracked-files=all` and confirm no *source* file has become
   invisible. Spot-check that `git check-ignore -v` reports nothing for
   `V.SMART/V.SMART.Shared/V.SMART.Shared.csproj` and `docs/kb/INDEX.md`.

9. **Correct R-14 in `docs/kb/risks/technical-debt-register.md`.** Rewrite the entry to state
   what is actually true, keep the id (KB-060's own rule: ids are stable, never renumbered),
   record the correction date, remove the "remove from history" action, and add the residual
   action that *is* real: the nested-`.gitignore` fragility and the CI guard. Re-rate the
   severity to match.

10. **Hand off to M0-07 explicitly**: the exact command M0-07 must add as a CI step, written
    in the baseline document and in the R-14 entry.

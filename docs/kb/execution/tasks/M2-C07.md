## Task Objective

Build `LineItemGrid`: the editable, virtualised, **keyboard-first** line-item grid that every
one of the ~65 React document editors uses to enter and edit document lines.

It is the editing *surface* only. It provides cells, a keyboard model, per-row validation
display, row add/duplicate/delete/reorder, and an "add lines from an upstream document"
hook. It computes **nothing** about the document.

Target: an operator entering a 200-line document keeps typing latency under 50 ms
([KB-050 §Performance targets](../../frontend-new/react-architecture.md#performance-targets)),
never touches the mouse, and never waits for a round trip between cells.

## Why This Task Exists

- **[KB-050](../../frontend-new/react-architecture.md#recommended-stack) calls it "the
  highest-value component in the app"** and states plainly that *"it will not come from a
  library"*. [ADR-003](../../decisions/ADR-003-react-stack.md) chose React Hook Form
  specifically because *"a 200-row line grid with controlled inputs re-renders
  unacceptably"*.
- **It is the gate on M3.** [KB-080 §9](../README.md#critical-path) notes that `M2-C07` and
  `M2-C08` are *not* on the M2 critical path — Customer Master is a master, not a document —
  *"but they are on **M3's** critical path and must complete inside M2 or M3-5 stalls."*
  M3-5 is Sales Order, the spine of the product.
- **It is the largest cost reduction available.** ~65 Upsert screens of 3,000–6,500 LOC each
  ([KB-015 §Page anatomy](../../architecture/frontend-architecture-existing.md#page-anatomy))
  collapse into one grid plus configuration.
- **It is the sharpest place where ERP logic could leak into React.** The existing line-entry
  behaviour lives in Razor `@code` as domain methods — item cascade, quantity-versus-balance
  arithmetic, duplicate prevention, row validation, resequencing. Every one of them is
  business logic. `LineItemGrid` must be built so that reimplementing them in TypeScript is
  *awkward*, not merely discouraged.

## Target Result

```tsx
<LineItemGrid<SalesOrderLine>
  columns={salesOrderLineColumns}   // cell editors declared per column
  control={form.control}            // RHF useFieldArray
  name="lines"
  rowErrors={serverRowErrors}       // keyed by row id, from the server
  onRowEvent={handleRowEvent}       // ONE event channel → one server call
  onPullFromUpstream={openPicker}
  readOnly={!canEdit}
  footer={<LineTotalsEcho />}       // provisional; server totals live in DocumentEditor
/>
```

**Keyboard model** — exactly as specified in
[KB-051 §Data display](../../frontend-new/design-system.md#data-display):

| Key | Action |
|---|---|
| `Enter` | Commit the row and create the next one, focus in its first editable cell |
| `Tab` | Next cell (wrapping to the next row's first cell at the end) |
| `Shift+Tab` | Previous cell |
| `Esc` | Revert the current row to its last committed values |
| `Ctrl+D` | Duplicate the current row |
| `Alt+↑` / `Alt+↓` | Reorder the current row |
| `↑ ↓ ← →` | Move between cells when not editing |
| `Delete` | Delete the current row (with confirmation when it holds data) |

Additional targets:

- **Virtualised** — 200 rows is the stated working size, 1,000 must not degrade.
- **Uncontrolled inputs via React Hook Form `useFieldArray`**; per-cell subscriptions only.
  Typing in row 187 must not re-render rows 1–186. Prove it with a render-count test.
- **Per-row validation badge** in a fixed gutter column, with the message reachable by
  keyboard and announced by `aria-live`, never a hover-only tooltip
  ([KB-051 principle 3](../../frontend-new/design-system.md#principles)).
- **Sticky footer row** showing line-level aggregates only (see *Business Logic*).
- **All numeric cells use decimal.js** via M2-C10's wrappers, right-aligned, tabular figures.
- **`onRowEvent` is the single channel** by which anything domain-flavoured leaves the grid.
  The grid never decides the consequence of an event; it reports it.
- **Paste from clipboard** into a range of cells (a genuine ERP need for 200-line entry),
  parsed through the decimal wrappers, with a preview of what will be applied.

## Business Logic

**Newly introduced — presentation and interaction only, with justification.**

`LineItemGrid` is new code. What is new is a *data-entry surface*: cells, a keyboard model,
row lifecycle operations, validation display.

**No ERP business rule is implemented client-side by this task.** This is the task where
that constraint is most likely to be violated, so it is stated concretely.

**Forbidden in this component, with the existing owner of each rule:**

| Behaviour | Owner |
|---|---|
| Computing line amount, discount, tax, or any document total | `CalculationService.UpdateTotalsAsync` — `V.SMART/V.SMART.Shared/Services/CalculationService.cs:12-114` (BR-CALC-001) |
| Resolving an item to its HSN, UOM, last price or tax rate | server; cf. `MfgPOUpsert.razor:2483` |
| Deciding whether an item is already on the document | server; cf. `MfgPOUpsert.razor:2558` |
| Quantity-versus-already-transacted balance arithmetic | server; cf. `MfgPOUpsert.razor:2569`, `:2631`; INV-013 |
| Deciding whether a row is valid beyond shape | server; cf. `MfgPOUpsert.razor:2654` |
| Deriving a delivery/due date | server; cf. `MfgPOUpsert.razor:2895` |
| Cancelling a line and reverting its quantity | server; cf. `MfgPOUpsert.razor:3113`, and M2-C08-03's command pattern |
| Any GST rate list or rate validation | server; BR-CALC-002 |

**The sticky footer is a slot, not a calculator.** [KB-051](../../frontend-new/design-system.md#data-display)
describes "running totals in a sticky footer row"; that is satisfied by a **caller-supplied**
node. If the caller chooses to render a provisional client-side echo for responsiveness, that
is permitted by [ADR-003 rule 1](../../decisions/ADR-003-react-stack.md#non-negotiable-rules)
— but it is the caller's choice, the value is labelled provisional, and the server's totals
overwrite it (M2-C08-02). `LineItemGrid` itself sums nothing.

**Enforcement, not just intent.** Add `__tests__/noBusinessLogic.test.ts` asserting that no
file in the component directory contains a multiplication or division applied to a
domain-named field, a hardcoded tax rate, or any of the field names `hsn`, `uom`, `cgst`,
`sgst`, `igst`, `tcs`, `balqty`. A constraint that only lives in a document gets violated the
first time someone is in a hurry.

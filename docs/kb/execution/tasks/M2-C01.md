## Task Objective

Create the React application project — **`frontend/nexgen-web/` — TO BE CREATED; no React
code exists anywhere in this repository today** — as a Vite 6 + React 19 + TypeScript
`strict` workspace, with ESLint (flat config) + Prettier, Vitest + React Testing Library +
MSW, a Playwright scaffold, the feature-sliced directory skeleton of
[KB-050](../../frontend-new/react-architecture.md#project-structure), and a frontend job
added to the CI workflow.

This task also **establishes the project's canonical frontend commands**
(`npm ci`, `npm run typecheck`, `npm run lint`, `npm run test`, `npm run build`,
`npm run e2e`). Every later M2-C task cites them. They cannot be verified before this task
runs, because there is no `package.json` at `frontend/nexgen-web/` to run them against —
see [Verification Commands](#verification-commands).

**Not in scope:** design tokens (M2-C04-01), authentication (M2-C02), the app shell
(M2-C03), the generated OpenAPI client (M2-B10), and any ERP screen or business behaviour.

## Why This Task Exists

- It is the **root of the entire M2-C branch** of the dependency graph
  ([KB-080 §9](../README.md#m2-c--react-foundation)): M2-C02, M2-C03, M2-C04-\*, M2-C05-\*,
  M2-C10 and M2-C11 all depend on it directly or transitively, and it sits on the project
  critical path (`M2-C01 → M2-C04-01 → M2-C05-01 → M2-D01`).
- [ADR-003](../../decisions/ADR-003-react-stack.md) is an accepted decision with **no
  implementation**. Until a project exists, the decision is unexecutable and the stack can
  drift by accident.
- **R-05 / INV-023 (Confirmed):** the repository has no test project and
  `.github/workflows/` is an **empty directory** — verified 2026-08-12. Frontend quality
  gates must be created with the app, not bolted on later. Principle 7
  ([KB-080 §3](../README.md#3-migration-principles)) requires testing to attach to the task
  that introduces the behaviour.
- **R-14 (Confirmed):** `frontend/vsmart-erp/dist/` and `frontend/vsmart-erp/.angular/cache/`
  are committed build output, and `.gitignore` currently ignores only `node_modules/`
  (`.gitignore:286`) — no `dist/`, no `coverage/`, no Playwright artefacts. Creating a
  second frontend without fixing the ignore rules reproduces R-14 immediately.
- **R-22 (Confirmed):** the existing UI loads MudBlazor 8.11 **and** Bootstrap 5. The
  React app installs **exactly one** component library — Mantine 7 per ADR-003 — and the
  `package.json` produced here is the enforcement point.

## Implementation Steps

1. **Confirm the baseline.** Run `git status --porcelain` (expect a clean tree post-M0-00),
   `ls .github/workflows/`, and read `.gitignore`. Record what M0-07/M0-08 actually left
   behind — this task's later steps branch on it.
2. **Create the branch** `migration/M2-C01-react-app-skeleton`.
3. **Scaffold** the project at `frontend/nexgen-web/` using
   `npm create vite@latest nexgen-web -- --template react-ts` from inside `frontend/`.
   Delete the template's demo assets (`src/assets/react.svg`, `src/App.css`,
   the counter markup in `App.tsx`).
4. **Pin Node.** Add `.nvmrc` containing `22`, and `"engines": { "node": ">=22 <23" }` to
   `package.json`.
5. **Install the dependency baseline** in the table above, pinning each to the major that
   ADR-003 names. Commit `package-lock.json` — `npm ci` requires it and CI uses `npm ci`,
   never `npm install`.
6. **Configure TypeScript strictly.** In `tsconfig.json` set at minimum:
   `strict: true`, `noUncheckedIndexedAccess: true`, `noImplicitOverride: true`,
   `exactOptionalPropertyTypes: true`, `verbatimModuleSyntax: true`,
   `noFallthroughCasesInSwitch: true`, and a `@/*` path alias to `src/*`. Mirror the alias
   in `vite.config.ts` and `vitest.config.ts`.
7. **Configure ESLint (flat).** `typescript-eslint` type-aware rules, `react-hooks`,
   `jsx-a11y` (a11y is a build-time gate, not a later pass — see
   [KB-051 §Accessibility commitments](../../frontend-new/design-system.md#accessibility-commitments-wcag-22-aa)),
   and import ordering. Add two `no-restricted-imports` rules that encode ADR-003:
   - ban imports from any component library other than `@mantine/*`;
   - ban direct imports from `shared/api/generated/**` outside `shared/api/**`
     (the generated client arrives in M2-B10; the rule is created now so it never has to be
     retrofitted).
8. **Configure Prettier** and wire `format` / `format:check` scripts. Do not add Husky
   hooks in this task — CI is the gate; local hooks are a separate opt-in.
9. **Create the directory skeleton** from KB-050 §Project structure, with `.gitkeep` in each
   empty directory. Create **no** components beyond `App.tsx`.
10. **Wire `providers.tsx`** with, in this order: `ErrorBoundary` (`react-error-boundary`),
    `MantineProvider` (bare default theme, `defaultColorScheme="auto"` — the **token layer
    is M2-C04-01**), `QueryClientProvider` with a `QueryClient` whose defaults set
    `retry: 1`, `refetchOnWindowFocus: false`, and `staleTime: 30_000`, and the i18n
    provider with an `en` resource bundle containing one key.
11. **Wire `router.tsx`** as a React Router v7 library-mode `createBrowserRouter` with a
    single route `/` rendering a placeholder page that shows the app name and build version.
    No auth guard here — guards are M2-C02.
12. **Configure Vitest**: `environment: 'jsdom'`, `setupFiles: ['src/test/setup.ts']`,
    `globals: false` (import explicitly), coverage via `v8` with thresholds set to the
    measured starting value so the number can only go up.
13. **Configure MSW** in `src/test/msw/` with an empty handler array and a `server.ts` wired
    into `setup.ts` (`beforeAll`/`afterEach`/`afterAll`). No handlers exist yet; the harness
    must, so that M2-C02 adds handlers rather than infrastructure.
14. **Write the smoke tests:**
    - `src/app/App.test.tsx` — renders `App` inside the providers and asserts the
      placeholder text. This test proves the provider stack composes.
    - `e2e/smoke.spec.ts` — Playwright loads the dev server and asserts the same text.
15. **Add the CI job.** Extend `.github/workflows/ci.yml` (created by M0-07) with a
    `frontend` job: `actions/setup-node@v4` with `node-version-file: frontend/nexgen-web/.nvmrc`
    and `cache: npm`, then `npm ci`, `npm run typecheck`, `npm run lint`, `npm run test --
    --run`, `npm run build`. Set `working-directory: frontend/nexgen-web`. Run Playwright in
    a **separate, non-blocking** job for now; it becomes blocking when the first real screen
    lands (M2-D01).
    *If `.github/workflows/ci.yml` does not exist at execution time, stop and report the
    task as **Blocked** on M0-07 — do not invent a parallel CI file.*
16. **Extend `.gitignore`** with the frontend artefact paths listed under
    [Target Result](#target-result). Verify with `git status --porcelain` after a build that
    no build output is staged.
17. **Verify the bundle budget.** Run `npm run build` and record the gzipped size of the
    initial chunk against KB-050's `< 250 KB gzip` target. Record the number; do not fail
    the task on it at this stage — record it as the baseline the shell (M2-C03) is measured
    against.
18. **Update documentation** per [Documentation Updates](#documentation-updates), including
    the verified-commands table in KB-083.
19. **Review the full diff**, confirm nothing under `V.SMART/` or `frontend/vsmart-erp/`
    changed, and commit.

## Business Logic

**Newly introduced — presentation only.** The only behaviour added is application
bootstrapping: provider composition, routing, and build/test configuration.

**No ERP business rule is implemented.** Project principle 3
([KB-080 §3](../README.md#3-migration-principles)) forbids ERP logic in React; ADR-003's
non-negotiable rules 1, 2 and 4 forbid client-side calculation, stock allocation, and
optimistic updates on money or stock. Nothing in this task computes anything.

## Task Objective

Create the Angular application workspace at **`frontend/nexgen-web/`** — replacing the React tree
that currently occupies that path — as an **Angular 22.x** (ADR-007's pinned major, owner decision
2026-08-20; the exact patch installed is recorded here, not assumed) + TypeScript `strict`
workspace with **PrimeNG at the matching major as the only component library**, ESLint +
Prettier, a unit-test harness that is **not** Karma, a Playwright scaffold, the directory skeleton
of [KB-050 §Project structure](../../frontend-new/react-architecture.md#project-structure), and the
existing CI `frontend` job re-pointed at it.

This task also **re-establishes the project's canonical frontend commands** (`npm ci`,
`npm run build`, `npm run lint`, `npm run test`, `npm run e2e`, and whatever Angular CLI names the
typecheck step). Every later `M2-C` task cites them, and KB-083's verified-commands table currently
records the **React** commands, which stop existing when this task lands.

**Not in scope:** design tokens (`M2-C04-01`, itself pending re-specification), authentication and
the permission store (`M2-C02`), the app shell (`M2-C03`), the generated OpenAPI client (`M2-B10`),
adopting the pilot's components (`M2-C11`), and any ERP screen or business behaviour.

### Two scope decisions this re-specification makes, and why

**1. The Angular workspace lives at `frontend/nexgen-web/`, and the React tree there is deleted in
the same commit.** ADR-007 leaves this to *"`M2-C01`'s re-scope … but the default is deletion in
the same change that scaffolds Angular: two frontend applications in one repository, only one of
them built, is how a stale tree starts"* (`ADR-007-angular-stack.md:223-225`). This file is that
re-scope, and it takes the default. Reusing the same path — rather than inventing a third frontend
directory — keeps `ci.yml`, `.gitignore` and every KB citation pointing where they already point;
`nexgen-web` was never a framework-specific name.

**2. The pilot at `frontend/vsmart-erp/` is still not touched by this task.** ADR-007 makes it the
*baseline* rather than landfill (`ADR-007-angular-stack.md:76-80`), but **adopting its components is
`M2-C11`'s job**, not this one's. This task copies its *patterns* (standalone bootstrap, functional
guard, functional interceptor — see KB-050 §*The Angular pilot*) and none of its files. Two task
ids in one branch is a reject ([KB-080 §19](../README.md#19-git-strategy)).

> `M2-C11`'s task file still describes *archiving* the pilot, which ADR-007 inverted. That file is
> **stale and out of scope here** — it is re-specified when it comes up. Do not act on it.

## Implementation Steps

1. **Confirm the baseline.** `git status --porcelain` (expect clean), `ls .github/workflows/`,
   read `.gitignore`, and record `node --version` / `npx ng version`. Later steps branch on these.
2. **Create the branch** `migration/M2-C01-angular-workspace`.
3. **Delete the React tree** at `frontend/nexgen-web/` with `git rm -r`, in this same branch. The
   deletion and the Angular scaffold are one commit-scope: at no point is a half-deleted tree the
   state of `master`.
4. **Scaffold** the workspace with the Angular CLI at major **22.x**
   (`ng new nexgen-web --standalone --routing --style=scss --strict` — confirm the flags against
   `ng new --help` at that version rather than trusting this line). Remove the CLI's demo markup.
5. **Pin Node.** `.nvmrc` with the verified major, and a matching `"engines"` entry.
6. **Install the dependency baseline** above. Commit `package-lock.json` — CI uses `npm ci`.
7. **Tighten TypeScript**: `strict: true`, `strictTemplates: true` (Angular compiler options),
   `noUncheckedIndexedAccess`, `noImplicitOverride`, `noFallthroughCasesInSwitch`, and an `@/*`
   path alias to `src/*`.
8. **Configure ESLint (flat)** with `angular-eslint` and `typescript-eslint` type-aware rules, the
   Angular template a11y rules enabled as **errors** (a11y is a build-time gate, not a later pass —
   [KB-051 §Accessibility commitments](../../frontend-new/design-system.md#accessibility-commitments-wcag-22-aa)),
   and two `no-restricted-imports` rules encoding ADR-007:
   - ban imports from any component library other than `primeng`/`@primeng/*`;
   - ban direct imports from `core/api/generated/**` outside `core/api/**` (the generated client
     arrives in `M2-B10`; the rule is written now so it never has to be retrofitted).
9. **Configure Prettier** and wire `format` / `format:check`. No Husky hooks — CI is the gate.
10. **Replace Karma.** Whatever the CLI generated, the unit runner is Jest or Vitest with Angular
    Testing Library. Record the choice and the reason in `README.md`.
11. **Create the directory skeleton** from KB-050 §Project structure (`core/`, `shared/`,
    `layout/`, `features/`), `.gitkeep` in each empty directory. Create **no** component beyond the
    root component and one placeholder page.
12. **Wire `app.config.ts`** with, at minimum: `provideRouter(routes)`,
    `provideHttpClient(withInterceptors([]))` — the array is empty, interceptors are `M2-C02` —
    `provideAnimationsAsync()`, `providePrimeNG({ theme: { preset: <bare preset> } })` with **no**
    custom token layer (`M2-C04-01` owns tokens), and the i18n provider with an `en` bundle of one
    key.
13. **Wire `app.routes.ts`** as a single route rendering a placeholder page showing the app name and
    build version, loaded with `loadComponent` so lazy routing is proven from commit one. **No auth
    guard** — guards are `M2-C02`.
14. **Environment configuration must not hardcode a host.** The API base URL comes from
    configuration and a missing value **fails loudly at startup**. Neither `environment.ts` nor
    `environment.prod.ts` may contain an API host literal. This is the pilot's defect
    (`frontend/vsmart-erp/src/environments/environment.ts:1-5` and `environment.prod.ts:1-4` both
    hardcode `http://localhost:5144`, so its production build points at localhost) and reproducing
    it is an automatic fail.
15. **Write the smoke tests:** one unit spec that renders the root component through the real
    `app.config.ts` providers — it exists to prove the provider stack composes, so a broken
    `providePrimeNG` or router registration fails here rather than three tasks later — and
    `e2e/smoke.spec.ts`, a Playwright spec asserting the same placeholder text.
16. **Re-point the CI jobs.** Edit the existing `frontend` and `frontend-e2e` jobs in
    `.github/workflows/ci.yml` to the Angular commands, keeping their current shape
    (`Checkout → hygiene guard → setup-node → npm ci → lint → format:check → test → build`, with
    e2e `continue-on-error: true`). Correct the stale comment at `ci.yml:27-31`. **Do not add a
    second workflow file.**
17. **Extend `.gitignore`** with the Angular artefact paths, then verify with
    `git status --porcelain` after a build that no build output is staged. `tools/check-no-build-output.sh`
    exists and must still pass.
18. **Measure the bundle** with a production build and record the initial-chunk gzip size in
    `frontend/nexgen-web/README.md` against KB-050's `< 250 KB gzip` target. Record the number;
    do not fail the task on it — it is the baseline `M2-C03` is measured against, and KB-050 states
    that the React baselines it used to carry were removed precisely because they say nothing about
    an Angular build.
19. **Update documentation** per [Documentation Updates](#documentation-updates).
20. **Review the full diff**, confirm nothing under `V.SMART/` or `frontend/vsmart-erp/` changed,
    and commit.

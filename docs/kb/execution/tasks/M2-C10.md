## Task Objective

Establish, in the React app, a single decimal module built on `decimal.js` — the library
[ADR-003](../../decisions/ADR-003-react-stack.md) names — through which **all** money,
quantity, rate, percentage and tax values are parsed, held, compared, formatted and
(where unavoidable) arithmetically combined. Then make the alternative impossible: add lint
rules and tests that fail the build when a monetary or quantity value is touched by
JavaScript's `number` arithmetic.

Proposed location: `frontend/nexgen-web/src/shared/lib/decimal/` — **TO BE CREATED**.
`src/shared/lib/` is named by
[KB-050 §Project structure](../../frontend-new/react-architecture.md#project-structure);
the `decimal/` subfolder and every file inside it are **proposed** by this task.

The complementary half of this task is a **prohibition**: the client never *owns* a
calculated result. Totals, taxes and stock allocations come from the server
(BR-CALC-001, BR-STK-001). The decimal module exists so the client can *display* and
*preview* those numbers exactly, not so it can compute them.

## Why This Task Exists

- **ADR-003 lists `decimal.js` under "Money display arithmetic"** and its non-negotiable
  rule 1 forbids reimplementing `CalculationService` in TypeScript. A library in
  `package.json` that nobody is required to use enforces nothing. This task turns the
  decision into a mechanism.
- **JavaScript `number` is IEEE-754 binary floating point.** `0.1 + 0.2 !== 0.3`.
  In an ERP that prices to `Companydetails.DecimalPlaces` (default **2**, Confirmed:
  `V.SMART/V.SMART.Shared/Data/Master/Company_Module/Companydetails.cs:208`) and carries an
  explicit per-document `RoundOff` field (Confirmed:
  `V.SMART/V.SMART.Shared/Data/OutSourcing/PurchasePo/PurchPo.cs:167`,
  `V.SMART/V.SMART.Shared/Data/SalesAndLabour/SalesInvoice/MfgInv.cs:210` with
  `IsRoundOffEnabled` defaulting to `true`), a one-paisa client/server disagreement is not
  cosmetic — it is a document that fails to reconcile against the printed invoice.
- **The server-side model is `decimal`, not `double`.** Every amount and quantity column in
  `V.SMART.Shared/Data/**` is C# `decimal` (Confirmed by inspection of the entity files in
  `source_files`). Deserialising `decimal` into a JS `number` silently changes the numeric
  type system at the HTTP boundary. This task defines the crossing rule.
- **It must land before the first editable grid.** `M2-C07` (`LineItemGrid`) depends on
  M2-C10 in [KB-080 §9](../README.md#m2-c--react-foundation) precisely because a line grid
  is where float arithmetic would otherwise appear first, in the highest-volume,
  lowest-visibility code in the app.
- **BR-CALC-001 (Confirmed)** states one engine computes every document's gross, discount,
  freight, taxable value, CGST/SGST/IGST, TCS, round-off and grand total:
  `CalculationService.UpdateTotalsAsync(ICalculationDocument)`. There is exactly one
  implementation and it is on the server. This task's rules are how that stays true when
  ~65 document editors are written in React.

**New, narrow investigation — record it.**

1. **The wire format for `decimal`.** Determine, from the running API and its OpenAPI
   document, whether a C# `decimal` currently serialises as a JSON **number** or a JSON

   Record what you find, including a negative result.

   half-away-from-zero) for the `RoundOff` field. If it cannot be determined from code

Record all three under a **new investigation id, INV-032 — "Decimal representation across
the API boundary"**, using the evidence format from

## Target Result

A module at `frontend/nexgen-web/src/shared/lib/decimal/` — **all paths proposed** —
exposing:

| Export | Purpose |
|---|---|
| `type Money` / `type Qty` (branded wrappers over `Decimal`) | Make a money value structurally distinct from a `number` so the compiler catches misuse. |
| `money(input: string \| number \| Decimal): Money`, `qty(...)` | The only constructors. Accept the wire value; reject `NaN`, `Infinity` and `undefined` loudly. |
| `fromApi(value: unknown): Money` | The single wire-boundary crossing point, implementing whatever INV-032 measures. |
| `toApi(value: Money): string \| number` | The reverse, matching the same contract. |
| `add`, `sub`, `mul`, `div`, `neg`, `abs` | Explicit, total functions over `Money`/`Qty`. There is no operator overloading in TS — arithmetic must be a function call, which is what makes the lint rule enforceable. |
| `eq`, `lt`, `lte`, `gt`, `gte`, `isZero`, `cmp` | Comparison. `===` on wrapped values is meaningless and must never be used. |
| `round(value, places, mode)` | Explicit rounding only. No implicit rounding anywhere else. |
| `format(value, { places, locale, currency? })` | Display. Uses `Intl.NumberFormat` with tabular output per [KB-051 §Typography](../../frontend-new/design-system.md#typography). |
| `parseUserInput(raw: string, { places }): Result<Money, ParseError>` | Input parsing: locale separators, blank, minus, partial input during typing. Returns a result, never throws, never silently yields `0`. |
| `ZERO`, `isMoney`, `isQty` | Constants and guards. |

Plus:

- **A documented precision policy.** Default display places come from
  `Companydetails.DecimalPlaces` (server-supplied, default `2`) — never hardcoded in a
  component. Until the settings endpoint exists, the module reads a single configurable
  default with a `TODO` naming the task that will supply it.
- **`Decimal` is configured once**, at module load, with an explicit precision and rounding
  mode, and `decimal.js` is imported **only** inside this module. Nothing else in the app
  imports it.
- **ESLint rules** (in `eslint.config.js`):
  1. `no-restricted-imports` — `decimal.js` may be imported only from
     `src/shared/lib/decimal/**`.
  2. `no-restricted-syntax` — ban `parseFloat`, `Number.parseFloat` and unary `+` coercion
     outside the decimal module.
  3. `no-restricted-properties` — ban `.toFixed()` app-wide; formatting goes through
     `format()`.
  4. A rule banning `Math.round`, `Math.floor`, `Math.ceil` outside the decimal module.
- **An architecture test** (Vitest) that greps the source tree and fails if `decimal.js`,
  `toFixed`, `parseFloat` or a bare arithmetic operator applied to an identifier matching
  `/amount|price|rate|qty|quantity|total|tax|discount|gross|net/i` appears outside the
  module. Lint catches the common cases; this test catches the ones written before the rule
  is configured or suppressed with an inline disable.
- **A written prohibition** in `frontend/nexgen-web/README.md` and in
  [KB-050](../../frontend-new/react-architecture.md): totals come from
  `POST /documents/calculate`; a local preview may be shown for responsiveness but is
  **overwritten by the server result before save**, and is visually marked as provisional.

## Implementation Steps

1. **Run INV-032 first.** Determine the wire format for `decimal`, the precision sources,
   and the server's rounding mode. Everything below depends on the answer to step 1a:
   1a. Inspect `V.SMART/V.SMART.Api/Program.cs` and the controllers for JSON serialiser
       configuration; call the running API's `CurrencyController` and read the raw JSON.
   1b. Confirm `Companydetails.DecimalPlaces` (`Companydetails.cs:208`) is the settings
       source, and search for any per-item quantity precision.
   1c. Search `CalculationService` for its rounding call. If ambiguous, record **Unknown**
       and raise it as an open question rather than choosing one.
2. **Create the branch** `migration/M2-C10-decimal-handling`.
3. **Create `src/shared/lib/decimal/decimal.ts`** — the only file in the app that imports
   `decimal.js`. Configure `Decimal.set({ precision: 34, rounding: <from step 1c>,
   toExpNeg: -9, toExpPos: 21 })`. If step 1c returned Unknown, use
   `Decimal.ROUND_HALF_UP`, add a prominent comment naming INV-032, and flag the assumption
   in the final report.
4. **Define the branded types** `Money` and `Qty`. Branding matters: without it, `Money` and
   `number` are interchangeable to the compiler and every rule below becomes advisory. Use a
   unique-symbol brand so a raw `Decimal` cannot be passed where `Money` is expected.
5. **Implement the constructors and the wire boundary** (`money`, `qty`, `fromApi`,
   `toApi`). `fromApi` must throw a named error on `null`/`undefined`/`NaN` rather than
   coercing to zero — a missing amount rendered as `0.00` is the exact class of bug this
   task exists to prevent.
6. **Implement arithmetic, comparison, rounding and formatting** as listed in
   [Target Result](#target-result). Keep every function total and pure. No function in this
   module may perform ERP arithmetic — there is no `calculateLineTotal`, no `applyTax`,
   no `computeGrandTotal`. If a caller wants one, the answer is an API call.
7. **Implement `parseUserInput`.** Handle: empty string, `-`, `.`, trailing separator during
   typing, thousands separators for the active locale, and more decimals than allowed. Return
   a discriminated result. It must never throw and never silently substitute `0`.
8. **Add the ESLint rules** listed above to `eslint.config.js`, with the decimal module
   itself exempted via an override block.
9. **Write the architecture test** `src/shared/lib/decimal/no-float-money.test.ts` that
   scans `src/**` (excluding the decimal module and test fixtures) for the banned patterns
   and asserts zero matches, printing every offending `file:line` on failure.
10. **Write the unit tests** listed under [Testing](#testing), including the classic
    float-failure cases as explicit regression tests.
11. **Document the prohibition** in `frontend/nexgen-web/README.md` (a short "Money and
    quantities" section) and add a cross-reference paragraph to
    [KB-050](../../frontend-new/react-architecture.md).
12. **Verify**: `npm run typecheck`, `npm run lint`, `npm run test -- --run`,
    `npm run build` — all from the command set established by M2-C01.
13. **Record INV-032**, update the tracker, review the diff, commit.

## Business Logic

**Newly introduced — presentation behaviour only.**

The behaviour introduced is numeric representation, parsing and formatting for display.
**No ERP business rule is implemented.** Specifically, this module contains no line-total,
tax, discount, freight, TCS, round-off, costing or stock-allocation logic. BR-CALC-001 and
BR-STK-001 remain solely server-side, and this task's lint and architecture tests exist to
keep them there.

The one behaviour that touches money semantics — the rounding mode — is **taken from the
server**, not chosen by the client. If it cannot be determined, it is recorded as Unknown
and raised, per [KB-002](../../source-of-truth-rules.md).

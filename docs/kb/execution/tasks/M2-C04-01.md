## Task Objective

Implement the token layer of [KB-051](../../frontend-new/design-system.md) as CSS variables
plus a Mantine 7 theme: semantic colour, typography, spacing, radius, elevation, motion,
breakpoints and density — authored as **two first-class palettes** (light and dark), not one
palette filtered into the other.

Deliver with it: a theme provider, a `light | dark | system` preference with a `system`
default, a theme toggle **component** (its placement in the header is M2-C03's job), and an
automated contrast test over every token pair used for text or UI boundaries.

Proposed location: `frontend/nexgen-web/src/shared/theme/` — **TO BE CREATED**. `src/shared/`
is named by [KB-050 §Project structure](../../frontend-new/react-architecture.md#project-structure);
the `theme/` subfolder and its file names are **proposed** by this task.

**Not in scope:** any component that consumes the tokens. No form control (M2-C04-02), no
modal or toast (M2-C04-03), no shell, sidebar or header (M2-C03), no `StatusBadge` component
— this task defines the *status colour tokens* it will use, and the component itself ships
with its first consumer, M2-C05-01.

## Why This Task Exists

- **Every other primitive depends on it.** M2-C04-02 and M2-C04-03 both consume these
  variables; M2-C03 cannot lay out a shell without spacing and breakpoint tokens. It is on
  the project critical path (`M2-C01 → M2-C04-01 → M2-C05-01 → M2-D01`,
  [KB-080 §9](../README.md#critical-path)).
- **Tokens are the only durable defence against R-22.** The current UI mixes MudBlazor 8.11
  and Bootstrap 5 (Confirmed,
  [KB-015 §Stack](../../architecture/frontend-architecture-existing.md#stack)). A single
  library is necessary but not sufficient — a second visual language appears the moment
  components start hardcoding colours. A token layer plus a lint rule banning raw hex makes
  that mechanically hard.
- **Density is a functional requirement here, not a taste.** Users are full-time operators
  working keyboard-first for whole shifts over dense structured data (ADR-003 §Context).
  KB-051 §Principles puts it first: 36 px default row height, 30 px compact, "more rows
  visible = fewer scrolls = faster work". The type scale reflects the same reality — the
  workhorse size is **12/18**, not 16, because it is what tables and form inputs use. That is
  a decision that only makes sense in an ERP, and it must be encoded in tokens rather than
  argued about per screen.
- **Contrast must be measured, not eyeballed.** KB-051 commits to WCAG 2.2 AA in **both**
  themes (≥ 4.5:1 text, ≥ 3:1 UI boundaries). Two hand-authored palettes across ~20 semantic
  tokens will contain a violation unless something checks. This task adds the check.
- **The persistence story has a real constraint that must be surfaced, not assumed away.**
  `UserThemePreference` exists and holds a **single `bool IsDarkMode`, defaulting to
  `false`** — Confirmed:
  `V.SMART/V.SMART.Shared/Data/Master/MasterScreeenManagement_Module/UserThemePreference.cs:20`.
  It **cannot represent `system`**. KB-051 asks for a `system` default. The schema and the
  spec disagree, and this task must record that rather than quietly dropping `system` or
  quietly changing the schema.

### Tokens

Reproduce [KB-051 §Tokens](../../frontend-new/design-system.md#tokens) exactly:

- **Colour** — the 16 semantic tokens (`--bg-canvas`, `--bg-surface`, `--bg-surface-raised`,
  `--bg-subtle`, `--border`, `--border-strong`, `--text-primary`, `--text-secondary`,
  `--text-disabled`, `--accent`, `--accent-subtle`, `--success`, `--warning`, `--danger`,
  `--info`, `--focus-ring`) with the light and dark values given in KB-051. **Semantic
  names only** — no component may reference a raw hue.
- **Typography** — `Inter` (UI) and `JetBrains Mono` (codes, quantities, amounts),
  self-hosted with `font-display: swap`; the six size tokens `--text-xs` (11/16) through
  `--text-2xl` (24/32), with **`--text-sm` (12/18) as the workhorse for table body and form
  inputs**. All numeric contexts get `font-variant-numeric: tabular-nums` and right
  alignment.
- **Spacing** — 4 px base scale: 4 · 8 · 12 · 16 · 24 · 32 · 48.
- **Radius** — `sm 4 · md 6 · lg 8 · full`. Nothing rounder; this is a data tool.
- **Elevation** — `0` flat, `1` card, `2` dropdown, `3` modal. Dark mode uses lighter
  surfaces rather than shadows.
- **Motion** — `fast 120ms`, `base 180ms`, `slow 240ms`, all `cubic-bezier(.2,0,0,1)`,
  every one gated on `prefers-reduced-motion`.
- **Breakpoints** — `≥1440` (primary target), `1024–1439`, `768–1023`, `<768`, per
  [KB-051 §Responsive behaviour](../../frontend-new/design-system.md#responsive-behaviour).
- **Density** — `default` (36 px rows/controls) and `compact` (30 px), exposed as a theme
  setting.

### Behaviour

- `system` is the default preference and follows `prefers-color-scheme` live, without a
  reload.
- The resolved scheme is written to `<html data-theme="light|dark">` **before first paint**
  (an inline script in `index.html`), so a dark-mode user never sees a white flash.
- Switching theme causes **no layout shift and no remount** — only CSS variable values
  change.
- The preference persists locally for now, with an explicit `TODO` naming the settings task
  that will move it to the server, and a recorded note that the existing
  `UserThemePreference.IsDarkMode` boolean cannot represent `system`.

### Enforcement

- An ESLint rule banning raw hex/`rgb()`/`hsl()` colour literals in `src/**` outside
  `shared/theme/tokens.css`.
- A test asserting the app's stylesheets contain no colour literal outside the token file.
- `contrast.test.ts`: every text-on-background and border-on-background token pair meets
  4.5:1 / 3:1 respectively, **in both themes**, computed rather than asserted by hand.

## Implementation Steps

1. **Run the investigation** described above and record it. In particular confirm
   `UserThemePreference.IsDarkMode` (`UserThemePreference.cs:20`) and the absence of an HTTP
   surface for `IUserThemePreferenceService`.
2. **Create the branch** `migration/M2-C04-01-design-tokens`.
3. **Author `tokens.css`.** `:root` carries the light palette; `[data-theme="dark"]` carries
   the dark palette. Both are written out in full — dark is **not** derived by `filter`,
   `invert`, or an opacity trick. Include every scale from
   [Tokens](#tokens): colour, type, spacing, radius, elevation, motion, density.
4. **Author `tokens.ts`.** Export a typed union of token names and typed accessors. This file
   is the single source the lint rule and the contrast test read, so a token added to CSS but
   not here fails the build — which is the point.
5. **Author `theme.ts`.** Map Mantine 7's `colors`, `primaryColor`, `fontFamily`,
   `fontFamilyMonospace`, `headings`, `spacing`, `radius`, `shadows`, `breakpoints` and
   `defaultRadius` onto the CSS variables. Do **not** duplicate values in JS: Mantine's
   CSS-variable theming (the reason ADR-003 chose it over a runtime style engine) means the
   theme should reference `var(--…)`, not restate hexes.
6. **Self-host the fonts.** Add Inter and JetBrains Mono as local `woff2` subsets with
   `font-display: swap` and explicit `@font-face` declarations. No CDN, no
   `fonts.googleapis.com` — a network dependency on first paint is a latency and privacy cost
   an internal tool should not pay. Record the added bytes against KB-050's
   `< 250 KB gzip` initial-bundle target.
7. **Author `global.css`.** A minimal reset, base typography from the tokens, a
   `:focus-visible` ring of 2 px at 2 px offset using `--focus-ring`, `tabular-nums` on
   numeric utility classes, and a `prefers-reduced-motion` block that neutralises every
   transition.
8. **Build `ThemeProvider.tsx`** wrapping `MantineProvider` with the theme, managing the
   colour scheme, and writing `data-theme` on `<html>`. Replace the bare provider in
   `providers.tsx`.
9. **Add the no-flash inline script** to `index.html`: read the stored preference, resolve
   `system` against `prefers-color-scheme`, set `data-theme` synchronously. Keep it under ten
   lines and comment why it cannot live in React.
10. **Build `useColorScheme.ts`** — tri-state preference, live `matchMedia` subscription for
    `system`, persistence, and a documented `TODO` naming the future settings task.
11. **Build `ThemeToggle.tsx`** — a three-state control (Light / Dark / System), keyboard
    operable, with an accessible name and `aria-pressed` or a radio-group role. It is
    exported but **not placed**; M2-C03 puts it in the header.
12. **Build `density.ts` and `breakpoints.ts`**, exporting the same numbers to CSS and TS so
    a media query and a JS check can never disagree.
13. **Write `contrast.test.ts`.** Compute WCAG 2.2 contrast ratios for every
    text-token × background-token pair and every border-token × background-token pair, in
    both themes, and assert the thresholds. If a KB-051 value fails, **report it as a finding
    and propose a corrected value — do not silently alter the spec**, and do not weaken the
    threshold.
14. **Write `theme.test.tsx`**: default is `system`; changing `prefers-color-scheme` while on
    `system` flips the resolved theme without a remount; explicit choices override; the
    preference survives a reload; the toggle is keyboard operable; `prefers-reduced-motion`
    disables transitions.
15. **Add the ESLint raw-colour rule** with an override for `tokens.css`, and a test that
    scans the built CSS for colour literals outside the token layer.
16. **Verify** with the M2-C01 command set, record the CSS + font byte cost, update
    documentation, amend INV-006, review the diff, commit.

## Business Logic

**Newly introduced — presentation behaviour only.**

The behaviour added is visual: token resolution, colour-scheme selection and density
selection. **No ERP business rule is implemented.** No token encodes a business decision; the
status colour tokens are named for document states (`--success`, `--warning`, `--danger`,
`--info`) but assign no meaning — the mapping from document status to token is
[KB-051 §Status vocabulary](../../frontend-new/design-system.md#status-vocabulary) and is
applied by `StatusBadge`, which ships with M2-C05-01.

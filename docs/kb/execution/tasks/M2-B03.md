## Task Objective

Write the **one document** that a developer opens before creating any of the 60–80
controllers still to come, and prove it against the two controllers that already exist.

The document consolidates what is currently spread across
[ADR-002](../../decisions/ADR-002-rest-api-layer.md),
[ADR-004](../../decisions/ADR-004-server-side-authorization.md),
[KB-041](../../api/api-readiness-assessment.md) and the outputs of
[M2-A02](M2-A02.md), [M2-A06](M2-A06.md) and [M2-B02](M2-B02.md) into a single, complete,
copy-and-adapt reference: route shape, authorization attributes, paging/sort/filter
contract, error contract, workflow-command pattern, naming, and the OpenAPI annotations the
generated client needs.

**This is the freeze point.** After this task, the contract is settled and later changes are
treated as breaking.

## Why This Task Exists

Three reasons, in order of force.

**1. It is the freeze point of the contract chain.** [KB-080 §9](../README.md#parallel-work)
marks the sequence strictly sequential:

```
M2-A06 (error contract) → M2-B02 (paging contract) → M2-B03 (template) → M2-B10 (TS client)
```

and [KB-080 §9 Risks](../README.md#risks) names the mitigation explicitly:
*"Freeze the contract at M2-B03; treat later changes as breaking and version them."*

> **Say this plainly in the document itself.** The chain must settle **before** controllers
> proliferate. [M2-B10](M2-B10.md) generates a TypeScript client from the OpenAPI document;
> generating that client from an unsettled contract means regenerating it and reworking
> every React component built on it. The whole chain's value is destroyed by starting B10
> early — and equally by treating B03 as a document that can be quietly amended later. A
> change after this task is a **versioned, breaking change**, not an edit.

**2. It is what makes 60–80 controllers mechanical.**
[ADR-002 §Consequences](../../decisions/ADR-002-rest-api-layer.md#consequences): *"One
template makes 60–80 controllers mechanical and parallelisable."* That is only true if the
template is written down completely enough to be followed without re-deriving decisions.
[KB-041](../../api/api-readiness-assessment.md) estimates item **B1** (the controllers) at
8–12 weeks of parallelisable work — an estimate that is only credible against a real
template.

**3. G2 will not close without it.** [KB-080 §9 Definition of Done](../README.md#definition-of-done):
*"G2 ticked, milestone review recorded, and the controller template demonstrably followed by
both existing controllers — **the template is only real once it has two independent
users**."* This task must therefore verify the template against both `AuthController` and
`CurrencyController`, and record any divergence as either a template correction or a
documented, justified exception.

Today the raw material exists but is scattered, and the only worked example is inconsistent
with itself: `CurrencyController` returns **two different 400 body shapes** —
`ValidationProblem(ModelState)` at `V.SMART/V.SMART.Api/Controllers/CurrencyController.cs:62`
and `:74`, versus `BadRequest(new { message })` at `:66`, `:79` and `:89` (Confirmed,
re-verified 2026-08-12). That is exactly the inconsistency
[R-24](../../risks/technical-debt-register.md#r-24--no-api-error-contract) records, and the
template is where it stops being possible.

## Investigation Requirements

No repository investigation is needed for the template's *content* — its inputs are three
merged tasks and two accepted ADRs.

One thing must be derived: **the complete verb-to-service-method mapping.** The template's
value is that a developer with a service interface can produce a controller without thinking.
That requires the mapping to be written out against the real convention table in
[KB-011](../../architecture/backend-architecture.md#business-service-conventions-observed-consistent),
including the awkward cases:

| Service convention | Controller action |
|---|---|
| `SearchWithDynamicFilterAsync(int, int, Dictionary<string,object>?)` | `GET /` via [M2-B02](M2-B02.md)'s typed query + adapter |
| `Get…ByIdAsync(int)` | `GET /{id:int}` |
| `Upsert…Async(TVm)` | **the awkward one** — one service method, two REST verbs |
| `CreateAsync(TVm)` / `UpdateAsync(int, TVm)` returning `(bool, string, TVm?)` | `POST /` → 201 + `Location`; `PUT /{id:int}` → 200 |
| `CanDelete…Async(int)` → `(bool, string)` | consulted **before** delete; `false` → **409** carrying the message verbatim |
| `Delete…ByIdAsync(int)` | `DELETE /{id:int}` → 204 |
| `IsDuplicate…Async(...)` | never its own endpoint — a 409 from create/update |
| `Search…Async(string)` typeahead | `GET /search?q=` or `GET /?…` — **decide and document one**, do not leave both |
| `GetNext…NoAsync(...)` | **not** an endpoint — document numbering is server-side and allocated inside the create transaction ([M2-B12](M2-B12.md)) |

The `Upsert…Async` case must be decided, not deferred: the template must state whether
`POST` and `PUT` both call `Upsert`, distinguished by the id, and what each returns. Record
the decision and its reasoning.

Record all of this in the document, and record the negative results too — "there is no
service convention for bulk operations, so the template does not define one" is a useful
finding that stops future sessions inventing one per controller.

## Existing Behavior to Preserve

This is a documentation task; it changes no runtime behaviour. What it must **describe
accurately**, and what any conforming controller must preserve:

- **BR-SO-001** — *A Sales Order cannot be deleted once any downstream document exists.*
  ([KB-030](../../business-rules/business-rule-inventory.md#br-so-001--a-sales-order-cannot-be-deleted-once-any-downstream-document-exists),
  Confirmed.) The template's delete section exists to preserve this class of rule: the
  controller calls `CanDelete…Async`, and on refusal returns **409** with the service's
  message **verbatim** in `title`. [ADR-002 §4](../../decisions/ADR-002-rest-api-layer.md#4-error-contract-applicationproblemjson-everywhere)
  states why: *"strings like 'Cannot delete this Sales Order as a Sales DC transaction
  exists.' are product UX written by the domain team. They are surfaced unchanged, never
  replaced with generic text."* The template must say this in a way that makes paraphrasing
  feel like the error it is.
- **The two-different-400-shapes defect** in `CurrencyController` (`:62`, `:74` vs `:66`,
  `:79`, `:89`) is the worked *counter*-example. Whether [M2-A06](M2-A06.md) has already
  fixed it or not, the template must show the correct mapping and name the anti-pattern.
- **Thin controllers.** [ADR-002 §2](../../decisions/ADR-002-rest-api-layer.md#2-contract-conventions-mandatory-for-every-controller):
  *"Controllers are thin: bind → authorize → one service call → map. No business logic."*
  The template must give a testable definition of "thin" — see *Target Result*.
- **Workflow commands are server-side and atomic.** ADR-002 §3. The client never orchestrates
  a multi-step business operation.

## Target Result

**A single new document: `docs/kb/api/controller-conventions.md` (TO BE CREATED)**, with a
`doc_id` allocated from the KB numbering scheme (check `docs/kb/INDEX.md` for the next free
`KB-0xx`; the API module currently holds KB-040 and KB-041). It must contain, at minimum:

1. **Scope and status.** That this document is **frozen** as of M2-B03, that it implements
   ADR-002 and ADR-004 rather than superseding them, and that a change to it after this point
   is a breaking API change requiring a version bump.
2. **A complete, compilable reference controller** — not a sketch. Every attribute, every
   using, the constructor, all six action shapes, one workflow command, and the print
   endpoint stub. A developer must be able to copy it and change the nouns.
3. **Route conventions** — `/api/v1/{resource}`, plural kebab-case, the shared route constant
   from [M2-B01](M2-B01.md), `{id:int}` constraints, and `POST /{id}/{verb}` for commands.
4. **Authorization** — `[Authorize]` + `[RequireScreen("…")]` on the class, `[RequireRight(...)]`
   per action, deny-by-default, and **how to find the right screen name**: the `Screens` table,
   seeded with 152 rows at `V.SMART/V.SMART.Shared/Data/ApplicationDbContext.cs:1151-1326`
   (Confirmed). Cross-reference [M2-B05](M2-B05.md)'s typed constants once they exist.
5. **List endpoints** — the [M2-B02](M2-B02.md) contract: `PagedQuery`-derived typed query
   record, `PagedResult<T>`, the sort allow-list, `pageSize` maximum, and the filter adapter.
6. **The error contract**, as a table a developer can check an action against:

   | Status | When | Body |
   |---|---|---|
   | 400 | model binding / `DataAnnotations` failure | `problem+json` with `errors` keyed by field |
   | 401 | unauthenticated / expired token | — |
   | 403 | screen-right denial | which screen + right |
   | 404 | not found | — |
   | **409** | business-rule refusal | `title` = the service's message **verbatim** |
   | 500 | unhandled | `traceId` only |

   With an explicit note that **400 and 409 are different things**: a 400 means the request
   was malformed; a 409 means the request was well-formed and the domain refused it. Getting
   this wrong is what produced the current inconsistency.
7. **Workflow commands** — `POST /{id}/{verb}`, the whole sequence server-side, with the
   `MfgPOUpsert.razor` client-orchestration anti-pattern named as what not to do
   (ADR-002 §3).
8. **Payloads** — the existing `…VM` ViewModels, unchanged. No parallel DTO hierarchy.
9. **The service-method mapping table** from *Investigation Requirements*, including the
   `Upsert…Async` decision.
10. **OpenAPI annotations** — the `[ProducesResponseType]` set every action must declare, so
    [M2-B10](M2-B10.md)'s generated client has accurate types for every status code. This is
    the section most likely to be skipped and the one B10 depends on most.
11. **A conformance checklist** — a short list a reviewer runs against a new controller
    before approving it. Objective items only.
12. **The two worked examples**, verified: `AuthController` and `CurrencyController`, each
    either conforming or carrying a documented, justified exception. `AuthController` will
    need one — it is not a resource controller (`POST /api/v1/auth/login` is a token
    endpoint, and ADR-002 §5 writes it that way).

**A testable definition of "thin".** Rather than the unfalsifiable "no business logic", the
document should give reviewable criteria, for example: an action body contains no `if` on a
domain value, no loop over domain data, no arithmetic on money or quantity, and no more than
one `await` on a service — the delete case (`CanDelete…Async` then `Delete…Async`) being the
one documented exception. The session may refine these, but must produce criteria a reviewer
can actually apply.

## Implementation Steps

1. Branch: `git checkout -b migration/M2-B03-controller-conventions`.
2. **Verify the prerequisites have merged**, by reading code rather than status fields:
   - `grep -rn "RequireScreen\|RequireRight" V.SMART/V.SMART.Api/` — M2-A02.
   - `ls V.SMART/V.SMART.Api/Contracts/` — M2-B02.

   - `grep -rn "ApiRoutes\|api/v1" V.SMART/V.SMART.Api/Controllers/` — M2-B01.
   If any is missing, **stop and report blocked**, naming which.
3. Read both controllers in full, and `V.SMART/V.SMART.Api/Contracts/` in full. The template
   must describe what is there, not what was planned.
4. Allocate the `doc_id` from `docs/kb/INDEX.md`. Do not guess a number.
5. Write `docs/kb/api/controller-conventions.md` with the twelve sections above.
6. **Compile the reference controller.** Do not ship a code block that has never been through
   a compiler. Create a scratch controller in `V.SMART/V.SMART.Api/Controllers/` over a real
   service, build, confirm 0 errors, then **delete it** and commit only the document. Report
   that you did this. A template with a typo is a typo repeated 60–80 times.
7. Verify both existing controllers against the checklist. For each divergence decide
   explicitly: **fix the template** (it was wrong) or **record an exception** (the controller
   is legitimately special). Do not fix the controllers in this task — that is
   [M2-A02](M2-A02.md)/[M2-A06](M2-A06.md)/[M2-B02](M2-B02.md) work, already done or
   deliberately out of scope. If a controller genuinely violates the settled contract, raise
   it as a follow-up task rather than fixing it here.
8. Cross-link: add the new document to `docs/kb/INDEX.md`, and reference it from
   [KB-041](../../api/api-readiness-assessment.md) and
   [KB-040](../../api/api-overview.md). A conventions document nobody can find is a
   conventions document nobody follows.
9. Add the **freeze statement** to [KB-080 §9](../README.md#9-m2--foundation)'s risk row, so
   the plan and the document agree on what "frozen" means.
10. Review the diff and commit. Do not push to `master`.

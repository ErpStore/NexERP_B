## Task Objective

Complete `DataGrid` by implementing the five non-happy-path states it must render, and by
wiring **server-side** export.

States, per [KB-051 §State patterns](../../frontend-new/design-system.md#state-patterns):

1. **Loading (first)** — skeleton rows matching the final column layout.
2. **Loading (refetch)** — previous data retained plus a subtle top progress bar.
3. **Empty (no data yet)** — illustration + explanation + primary action.
4. **Empty (filtered to nothing)** — distinct copy + **Clear filters**.
5. **Error** — the server's message, the `traceId`, and Retry. Plus the two specialised
   error cases: **403 → `PermissionDeniedState`**, and **409 → the server's business-rule
   message rendered verbatim**.

Export: a toolbar action that requests a file from a server endpoint and saves it. React
never constructs a spreadsheet, CSV or PDF.

## Why This Task Exists

- **It is on the M2 critical path.** [KB-080 §9 Critical Path](../README.md#critical-path)
  runs `… → M2-C05-01 → M2-C05-03 → M2-D01`. Notably it is *this* child, not M2-C05-02, that
  the vertical slice waits on — because gate **G2** requires *"… server paging, validation,
  error contract, **Excel export**"*.
- **The empty/loading/error triad is a requirement of the component, not a later polish
  pass.** [KB-051](../../frontend-new/design-system.md#data-display) lists
  *"empty/loading/error states built in"* among `DataGrid`'s defining properties. A grid
  shipped without them ships a defect.
- **Business-rule messages are product UX and must not be rewritten.**
  [KB-050 §Error handling](../../frontend-new/react-architecture.md#error-handling) requires
  a 409 to surface *"the **server's message verbatim** — these strings are product UX"*. The
  strings are real, specific, and were written for users. Example, **Confirmed** 2026-08-12:
  `"Cannot delete this Sales Order as a Sales DC transaction exists."` at
  `V.SMART/V.SMART.Shared/BusinessLayer/BusinessService/SalesService/MfgPoService.cs:488`
  (BR-SO-001). Replacing that with "An error occurred" destroys information the user needs
  and that no client can reconstruct.
- **Export already exists server-side and must be reused, not rebuilt.**
  [ADR-005](../../decisions/ADR-005-reporting-and-printing.md) is explicit: Excel
  export/import stays server-side behind endpoints. `ExcelExportService` is already there
  (`V.SMART/V.SMART.Shared/Services/ExcelExportService.cs:24`, `:113`).

## Target Result

- `DataGrid` renders each of the five states distinctly, and a caller can override any of
  them without forking the component.
- **First load:** `<Skeleton>` rows, one per expected page row up to a cap, with the real
  column widths so the layout does not jump when data arrives. Never a centred spinner on a
  blank page.
- **Refetch:** previous rows stay; a 2 px indeterminate progress bar appears at the top of
  the grid; the grid is not disabled and focus is not moved.
- **Empty (no data):** `<EmptyState>` with an illustration, a caller-supplied noun
  ("No customers yet"), and a caller-supplied primary action.
- **Empty (filtered):** distinct copy ("No results for these filters") plus a **Clear
  filters** button that resets the URL query state via `useDataGridQuery`. The component
  distinguishes the two cases by whether any filter is active — not by guessing.
- **Error:** `<ErrorState>` showing `problem.title` **verbatim**, `problem.detail` when
  present, the correlation id in a copyable form, and Retry.
- **403:** `<PermissionDeniedState>` naming the screen right that is missing, inline — not a
  redirect ([KB-050 §Error handling](../../frontend-new/react-architecture.md#error-handling)).
- **409:** rendered as an inline alert or toast with the server's message verbatim. Never
  reworded, never prefixed with "Error:", never truncated, never passed through an i18n
  lookup that could fail to a key.
- **Export:** a toolbar menu (`Excel` / `CSV`) that issues one request to the server export
  endpoint carrying **the current sort and filter state**, receives a blob, saves it using
  the server-supplied filename, and shows progress while it runs. Long exports do not freeze
  the grid. If the export fails, the server's message is shown, not a generic one.

## Business Logic

**Preserved unchanged — display only.**

**No ERP business rule is implemented client-side by this task.** The component makes no
domain decision. Its single obligation with respect to business logic is *fidelity of
transport*: a business-rule refusal produced by a server service — for example
`"Cannot delete this Sales Order as a Sales DC transaction exists."`
(`V.SMART/V.SMART.Shared/BusinessLayer/BusinessService/SalesService/MfgPoService.cs:488`,
BR-SO-001) — must reach the user's eyes byte-for-byte as the server wrote it.

Forbidden: rewriting, shortening, sentence-casing, prefixing, appending, mapping to a
generic string, or routing through an i18n key lookup that can silently fall back. These
messages are product UX authored for ERP operators and often name the exact downstream
document blocking the action; a generic replacement makes the system unusable in precisely
the moments it matters.

Equally forbidden: generating any exported file in the browser. Export is a server
capability ([ADR-005](../../decisions/ADR-005-reporting-and-printing.md)); the client
requests bytes and saves them.

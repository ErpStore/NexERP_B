## Task Objective

Retire `frontend/vsmart-erp/` — the Angular 19.2 + PrimeNG 19.1 learning pilot — from the
active repository, after extracting the two things worth keeping (the proven
`AuthController` → `CurrencyController` → SPA path, and the de-facto `LoginResponse`
contract shape) into the knowledge base as text.

**The decision to archive rather than convert is already taken** — see
[KB-015 §The Angular 19 pilot](../../architecture/frontend-architecture-existing.md#the-angular-19-pilot-frontendvsmart-erp)
("the Angular project should be archived, not converted"),
[ADR-003 §Consequences](../../decisions/ADR-003-react-stack.md#consequences) ("The Angular
pilot is archived, not converted"), and [KB-080 §9](../README.md#m2-c--react-foundation),
which schedules this task. **This task executes that decision; it does not re-open it.**

It also closes **R-14** for this directory: `frontend/vsmart-erp/dist/` and
`frontend/vsmart-erp/.angular/cache/` are committed build output.

## Why This Task Exists

- **R-34 (Confirmed, [KB-060](../../risks/technical-debt-register.md)):** "Angular pilot
  will become dead code once React starts." M2-C01 starts React. From the moment
  `frontend/nexgen-web/` exists, `frontend/vsmart-erp/` is a second, unmaintained frontend
  in the same repository — two apps, two dependency trees, two ways to log in, and a
  standing invitation to fix a bug in the wrong one.
- **R-14 (Confirmed):** `frontend/vsmart-erp/dist/` and `frontend/vsmart-erp/.angular/cache/`
  (including `.db-lock` files) are tracked. `.gitignore:286` ignores `node_modules/` and
  nothing else relevant. Leaving a dead project *and* its committed build output is the
  worst of both.
- **Security hygiene.** The pilot's `auth.service.ts:29` defines `TOKEN_KEY = 'vsmart_jwt'`
  and lines 34, 60, 67 and 75 read/write the JWT (and the whole `LoginResponse`) in
  `localStorage`. [ADR-003 rule 5](../../decisions/ADR-003-react-stack.md#non-negotiable-rules)
  explicitly diverges from this because it is XSS-exposed. A working, runnable example of
  the rejected pattern sitting in the repository is a copy-paste hazard for every engineer
  who joins.
- **Configuration hazard.** `frontend/vsmart-erp/src/environments/environment.prod.ts:3`
  sets `apiBaseUrl: 'http://localhost:5144'` — the **production** environment file points at
  localhost. Confirmed by inspection 2026-08-12.
- **Its knowledge is worth more than its code.** INV-021 already recorded what the pilot
  proves. This task makes sure that record survives the deletion.

## Implementation Steps

1. **Confirm M2-C01 landed.** `ls frontend/nexgen-web/package.json` must succeed. If it does
   not, stop and report **Blocked** — never remove the only SPA in the repository.
2. **Inventory what is tracked.** Record, before changing anything:
   - `git ls-files frontend/vsmart-erp/ | wc -l`
   - `git ls-files frontend/vsmart-erp/dist/ | wc -l`
   - `git ls-files frontend/vsmart-erp/.angular/ | wc -l`
   These numbers go into the final report and into the INV-021 amendment. If the `dist/` and
   `.angular/` counts are already zero, M0-08 handled them — record that as a negative
   result and do not claim the credit.
3. **Choose and record the archive method.** Two acceptable options; pick one, state it in
   the commit message:
   - **(a) Tag and delete (default).** Create annotated tag
     `archive/angular-pilot-2026` on the current commit with a message explaining what the
     pilot was, then `git rm -r frontend/vsmart-erp`. Cleanest tree; full recovery via
     `git checkout archive/angular-pilot-2026 -- frontend/vsmart-erp`.
   - **(b) Move to `archive/angular-pilot/`.** Keeps the code visible in the working tree.
     Requires CI path-ignores and a prominent `ARCHIVED.md`. Only choose this if the owner
     explicitly wants the code browsable without git commands.
   Do **not** invent a third option, and do not rewrite history — history rewriting is
   M0-05's job and is already done by G0.
4. **Extract the retained knowledge first.** Before deleting anything, update
   [KB-015](../../architecture/frontend-architecture-existing.md): rewrite the Angular-pilot
   section in the past tense and inline the four facts in
   [Existing Behavior to Preserve](#existing-behavior-to-preserve), each with its
   `file:line` evidence **as it was at deletion time**, because those lines will no longer
   be resolvable afterwards. This ordering matters: deleting first makes the citations
   unverifiable.
5. **Check for inbound references.** Grep the whole repository for `vsmart-erp`,
   `primeng`, `primeflex` and `@angular` outside the directory itself — including
   `.gitignore`, `.github/`, `docs/`, and any `.sln`/`.csproj`. Fix or remove every hit.
   Record the list. (Expected: `.gitignore`, `.github/copilot-instructions.md`, and several
   `docs/kb/` files. `docs/kb/` references that *describe* the pilot historically are
   updated, not deleted.)
6. **Execute the chosen method** from step 3.
7. **Clean `.gitignore`.** Remove any rule that exists solely for the Angular project. Keep
   the generic `node_modules/`, `dist/` and cache rules — `frontend/nexgen-web/` needs them.
8. **Clean CI.** Confirm `.github/workflows/ci.yml` has no Angular job and no path filter
   naming `vsmart-erp`.
9. **Verify nothing else broke.** `dotnet build V.SMART/V.SMART.Api/V.SMART.Api.csproj`
   (0 errors expected) and the full frontend command set from M2-C01.
10. **Close the risks** in [KB-060](../../risks/technical-debt-register.md): R-34 Closed with
    the date and this task id; R-14 amended to state precisely which part is closed.
11. **Update the registry and tracker**, review the diff (it will be large and almost
    entirely deletions — check that every deletion is inside `frontend/vsmart-erp/`), and
    commit.

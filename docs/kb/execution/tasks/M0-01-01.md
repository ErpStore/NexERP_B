## Task Objective

Produce an authoritative, reproducible reconciliation between:

1. every `Sp_*` procedure name the application **references** from C# / Razor, with at least
   one `file:line` citation for each; and
2. every procedure name for which DDL **exists** in
   `Existing Store Procedures/StoredProcedures/`, taken from the `CREATE … PROCEDURE`
   statement inside each file rather than from the file name.

The output is a three-way classification — *scripted*, *missing*, *scripted-but-never-referenced* —
in a human-readable KB document and a machine-readable manifest, plus a re-runnable script
that regenerates the reference side of the comparison. This is the worklist a DBA executes
in M0-01-02, and it is the artefact reviewers check the resulting capture against.

**This task requires no database access.** Everything it needs is in the repository.

## Why This Task Exists

**R-04 (Critical, Confirmed)** in [KB-060](../../risks/technical-debt-register.md) states
that 81 of 94 stored procedures have no DDL in source control, and
[ADR-005](../../decisions/ADR-005-reporting-and-printing.md) makes fixing R-04 a mandatory
prerequisite for the entire reporting and printing strategy. G0's first exit criterion
([KB-080 §7](../README.md)) cannot pass until the procedures are captured.

You cannot capture a set you have not enumerated. Handing a DBA the instruction "script the
missing procedures" without a precise, evidenced list produces one of two failures: a
partial capture that is discovered months later when a report fails in production, or a
capture of *everything in the database*, including procedures the application never calls,
which pollutes source control and hides the real dependency surface.

There is also a concrete, already-observed reason not to trust file names:

> **Finding:** `Existing Store Procedures/StoredProcedures/Sp_Print_PurchaseOrder.sql`
> declares `[dbo].[Sp_Print_PurchaseOrder]`, but no C# or Razor file references that name.
> The application calls `Sp_Print_PurchasePo`, for which no DDL exists.
> **Evidence:** `Existing Store Procedures/StoredProcedures/Sp_Print_PurchaseOrder.sql:1`;
> `V.SMART/V.SMART.Shared/Pages/OutSourcing_Module_pages/PurchOrSubConPO_Pages/PurchasePoDetails.razor:306`;
> `V.SMART/V.SMART.Shared/Pages/OutSourcing_Module_pages/PurchOrSubConPO_Pages/PurchPOUpsert.razor:4596`;
> `V.SMART/V.SMART.Shared/Pages/Planning_Module_Pages/Authorization_Pages/Authorization.razor:723`.
> **Business rule:** n/a.
> **Confidence:** Confirmed.
> **Last verified:** 2026-08-12.

That single mismatch changes the headline number from 81 missing to **82** missing, and it
is exactly the class of finding this task exists to surface systematically. A name that is
referenced but never deployed anywhere would be a live latent defect — a report screen that
throws the moment a user opens it — and this reconciliation is the cheapest place in the
whole plan to detect one.

## Existing Behavior to Preserve

All of it. This task adds documentation, a manifest and a script. It changes no application
code, no SQL, and no configuration.

Two behaviours must be understood because they define what "referenced" means, and both are
**Confirmed**:

1. **Analytical reports.**
   `ReportExecutor.ExecuteAsync<T>` builds `string sql = $"EXEC dbo.{procedureName}";`
   (`ReportExecutor.cs:27`), appends the parameter names, and runs it through `FromSqlRaw`
   with `AsNoTracking()` into a keyless entity type (`ReportExecutor.cs:35-39`), after
   `SetCommandTimeout(300)` (`ReportExecutor.cs:25`). `ExecuteDataTableAsync` takes the
   second path, setting `CommandType.StoredProcedure` with the same 300-second timeout
   (`ReportExecutor.cs:105-107`). `procedureName` is a plain string with no validation, so a
   name that does not exist in the database fails only at run time, wrapped in
   `Exception($"Error while executing procedure: {procedureName}", ex)` (`ReportExecutor.cs:43-45`).
2. **Printed documents.**
   `ReportService.Generate_Report(int id, string fileName, string parameter, bool cancel, string screenName, string procedureName)`
   (`ReportService.cs:40`) loads a FastReport `.frx`, injects the tenant connection string
   (`ReportService.cs:71`), and then **requires `Sp_Print_CompanyDetails` unconditionally**:
   `if (report.GetDataSource("Sp_Print_CompanyDetails") is not TableDataSource dsCompany) throw …`
   (`ReportService.cs:74-77`). The document's own procedure is resolved next
   (`ReportService.cs:81-84`). The same `Sp_Print_CompanyDetails` requirement repeats in
   `GenerateSalarySlipReport` (`ReportService.cs:200-202`) and `Generate_Attendance_Report`
   (`ReportService.cs:328-331`).

   **Consequence, and it must appear in the reconciliation document:** `Sp_Print_CompanyDetails`
   is a hard dependency of *every* printed document, not one report among many. It is one of
   the 13 already scripted; losing it breaks all printing at once.

### Manifest schema (exact)

`db/stored-procedures/manifest.csv`, UTF-8, LF line endings, header row required:

```
procedure_name,status,scripted_file,reference_count,live_reference_count,first_reference,notes
```

| Column | Meaning |
|---|---|
| `procedure_name` | The name exactly as it appears in the source reference (or, for `unreferenced`, as declared in the `.sql` file) |
| `status` | `scripted` · `missing` · `unreferenced` · `case_mismatch` |
| `scripted_file` | Repo-relative path to the existing `.sql`, or empty |
| `reference_count` | Total matches in `.cs`/`.razor`, including commented-out lines |
| `live_reference_count` | Matches excluding lines that are commented out |
| `first_reference` | `path:line` of the first **live** reference; if there is none, the first commented one, marked in `notes` |
| `notes` | Free text — must be non-empty for every row whose `status` is not `scripted` |

     --exclude-dir=obj --exclude-dir=bin V.SMART | sort -u | wc -l

   Expected: `94` and `13` (both Confirmed on 2026-08-12). If either differs, **stop and
   record why** in the KB document before continuing — a changed count means the repository
   moved and every downstream number must be regenerated, not patched.

   Note the scoping deliberately: `--include=*.cs --include=*.razor` limits the search to
   application code, and restricting to `V.SMART/` excludes the `.sql` files themselves, the
   knowledge base, and `obj/`/`bin/` build output. INV-009 recorded the unscoped form
   (`grep -rhoE "Sp_[A-Za-z0-9_]+" | sort -u`); run from the repository root today it returns
   **110**, because it also matches procedure names quoted inside the `.sql` files and inside
   `docs/kb/` — including this task file. That is a *superset*, not the referenced set.
   **Confirmed 2026-08-12.** Use the scoped form, state it in the methodology section, and
   note the discrepancy so the next reader does not "correct" 94 upwards.

3. **Extract the declared names from the 13 `.sql` files** — from the DDL statement, never
   from the file name:

   ```bash
   grep -rniE "(CREATE|ALTER)[[:space:]]+(OR[[:space:]]+ALTER[[:space:]]+)?PROC(EDURE)?[[:space:]]+[^[:space:]]+" "Existing Store Procedures/StoredProcedures/"
   ```

   Record, for each file, the file name, the declared name, and whether they agree. Note that
   the files use mixed casing (`CREATE OR ALTER procedure`, `Create Or ALTER Procedure`),
   mixed bracketing (`[dbo].[Sp_…]` vs bare `Sp_…`), and that several begin with a UTF-8 BOM.
   All three matter to whoever writes the deployment script in M0-01-03 — record them.

4. **Build the reference index.** For every one of the referenced names, capture every
   `path:line` where it occurs, and mark whether the line is commented out (`//`, `/* */`,
   or `@* *@` in Razor). Write `db/tools/sp-inventory.sh` to do this, so the result is
   reproducible rather than hand-assembled. The script must:
   - take no arguments and run from the repository root;
   - emit `procedure_name<TAB>path:line<TAB>commented(yes|no)` to stdout, sorted;
   - use only `grep`/`sort`/`sed`-class tooling available in Git Bash on Windows and in a
     Linux CI container;
   - contain no connection string, host name, or credential.

5. **Classify every name** into exactly one of four buckets, comparing the two sets from
   steps 2–4 **case-insensitively** (SQL Server identifier comparison follows database
   collation, which is case-insensitive by default — record this as **Inferred**, since the
   live databases' collation has not been observed from this session):

   | Status | Definition |
   |---|---|
   | `scripted` | Referenced from code **and** declared in one of the 13 files, exact match |
   | `case_mismatch` | Referenced and declared, but the two spellings differ only in case |
   | `missing` | Referenced from code, no DDL anywhere in the repository → M0-01-02 worklist |
   | `unreferenced` | Declared in a `.sql` file but referenced nowhere in `.cs`/`.razor` |

   You are expected to find at least one `case_mismatch` (`Sp_Print_MFGDC` declared,
   `Sp_Print_MfgDC` called) and at least one `unreferenced` (`Sp_Print_PurchaseOrder`).
   **Verify both yourself rather than copying them from this task file**, and report any
   others you find.

6. **Flag the highest-consequence findings explicitly**, each in the KB-083 evidence format,
   because these are what a reviewer actually needs:
   - any name whose only references are commented out — a candidate for deletion rather than
     capture, and a decision that belongs to a human, not to you;
   - any `unreferenced` scripted procedure — it may be dead, or it may be called from a
     FastReport `.frx` template or from another procedure, neither of which this grep sees.
     **State that limitation.** Do not conclude "dead code" from a C#/Razor grep alone; the
     `.frx` templates under `V.SMART/V.SMART.Shared/wwwroot/templates/` bind data sources by
     procedure name, and confirming that is out of scope here;
   - `Sp_Print_CompanyDetails` as the universal print dependency (see *Existing Behavior*);
   - the corrected missing-count (expected **82**, not 81) with the arithmetic shown.

7. **Create `db/stored-procedures/`** with `README.md` and `manifest.csv` only. Do **not**
   create empty or stub `.sql` files — a stub that looks like DDL and is not is worse than an
   absence, because the deployment script in M0-01-03 would happily deploy it.

   `README.md` must state the conventions M0-01-02 is required to follow:

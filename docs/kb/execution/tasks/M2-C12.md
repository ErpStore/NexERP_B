# M2-C12 — Re-specify the superseded M2-C / M2-D task tree for Angular

| Field | Value |

## Objective

Remove the `⛔ STOP — this specification is superseded` banner from all **25** task files in the
`M2-C` and `M2-D` trees by re-deriving their stack-specific content against
[`ADR-007`](../../decisions/ADR-007-angular-stack.md) and the Angular rewrite of
[KB-050](../../frontend-new/react-architecture.md), so that each becomes selectable again.

**This task creates no application code.** It is documentation only.

## Why now, and why this task exists at all

The banner — **byte-identical in all 25 files** — names its own release condition:

> **Gating task:** **`M2-C00`** rewrites [KB-050](../../frontend-new/react-architecture.md) for
> Angular. Until that lands there is no authoritative structure to specify against, which is
> precisely why these files were left stale rather than rewritten in a hurry against a guess.

`M2-C00` landed on `master` at `0da6a35` (2026-08-21) and `M2-C01` at `2dd4e53`, so the
authoritative structure now exists in two forms: the rewritten KB-050, and a **real Angular
workspace on disk** at `frontend/nexgen-web/`. The condition is satisfied and the deferral is over.

**The precedent for the work is `M2-C00` itself**, which rewrote KB-050 *and* re-specified
`M2-C01` in the same change. That is the only reason `M2-C01` was selectable. This task does for
the remaining 25 what `M2-C00` did for one.

**Until this task lands, the entire frontend tree is unreachable.** Dependency-wise `M2-C04-01`,
`M2-C10`, `M2-C04` and `M2-C02` are released; every one of them is refused at selection step 4
because of the banner. No amount of merging changes that.

> **G0 is not met** (`task-tracker.md` gate table: `M0 | 24 | 12 | G0 | ⬜ Not met`). This task
> runs ahead of it as a **documentation-only** task, the same deliberate exception recorded for
> `M2-A01-01` in tracker footnote ¹⁸. It writes no code, touches no schema and changes no
> runtime behaviour, so nothing G0 protects is at risk.

## Scope

For **each** of the 25 files listed in `source_files`:

1. **Delete the ⛔ banner block** — and only once the file below it no longer needs it.
2. **Re-derive every stack-specific instruction** into its Angular equivalent, per the banner's
   own list: stack-specific instructions, file paths under `frontend/nexgen-web/`, component
   APIs, test-harness detail, and commands.
3. **Record the re-specification** in the file, in the shape `M2-C01` uses — a short note stating
   it was re-specified for Angular by `M2-C12`, on what date, and that the React implementation
   history is not deleted from the record.

Then, once per tree:

4. **Update the tracker rows** for all 25 so their status reflects the real remaining blocker
   (dependency, gate, or none) rather than the supersession.
5. **Update [`dependency-graph.md`](../dependency-graph.md)** where it describes the M2-C tree as
   React-shaped.

### The translation table this task must apply consistently

Derive from `ADR-007` and the **actual** `frontend/nexgen-web/` workspace, not from memory:

| React-era | Angular equivalent |
|---|---|
| React component / `.tsx` / JSX | standalone Angular component / `.component.ts` + `.component.html` |
| hooks (`useState`, `useEffect`, …) | signals, `computed`, `effect`, lifecycle hooks |
| Zustand store | injectable service holding signals, exposed read-only via `asReadonly()` |
| TanStack Query | `HttpClient` + service, per KB-050's data-access section |
| React Hook Form + Zod | typed Reactive Forms + `Validators` |
| Mantine | PrimeNG |
| Vite / `vite.config.ts` | Angular CLI / `angular.json` |
| React Testing Library | `@testing-library/angular` |
| React Router | `@angular/router`, functional `CanActivateFn` guards |
| `frontend/vsmart-erp/` (pilot) | `frontend/nexgen-web/` (the app) |

Commands must match the **verified** Angular table in
[KB-083 § Verified repository commands](../prompt-template.md#verified-repository-commands) —
`npm run typecheck`, `npm run lint`, `npm run test:ci`, `npm run build`, `npm run e2e`,
`npm run format:check`. Do not invent a command; if one is needed that is not in that table, say
so in the file rather than guessing.

## Out of Scope

- **Implementing any of the 25 tasks.** This task re-specifies; it does not build.
- **Any change under `frontend/`, `V.SMART/`, `tests/` or `.github/`.** The diff is confined to
  `docs/kb/`.
- **Changing what a task is *for*.** Intent, ERP behaviour, acceptance-criteria *semantics*,
  `business_rules`, `depends_on`, priority, estimate and gate all stay as they are. This task
  changes *how*, never *what* or *whether*.
- **The `file:line` evidence about the existing Blazor implementation.** The banner is explicit
  that this survives — it was never a React decision. It must come through byte-identical unless
  a citation is provably wrong, and any such correction is called out individually.
- **`M2-C00` and `M2-C01`** — already re-specified; they carry no banner and must not be touched.
- **Deleting any task file.** A task made obsolete by ADR-007 is *recorded* as such and routed to
  the owner (see `M2-C11`/Q-38 below), never removed.

## Implementation Requirements

1. **Work one file at a time, and keep them consistent.** The 25 must read as one coherent tree,
   not 25 independent rewrites. Apply the translation table uniformly.
2. **Re-verify before citing.** A task file's *Current Implementation* section is a hypothesis
   (CLAUDE.md). Any `file:line` citation into `frontend/nexgen-web/` must be checked against the
   tree as it exists; Blazor citations are preserved, not re-derived.
3. **Never invent a component API.** If PrimeNG's equivalent of a named Mantine component is not
   obvious from `ADR-007` or the workspace, record it as an open question rather than guessing.
4. **Preserve the audit trail.** Each file keeps its history: state that the React specification
   was superseded, not that it never existed.
5. **Claim ids correctly.** Any new Q/R/INV/KB id must be checked against
   `git branch --no-merged master` first — four cross-branch id collisions have already occurred,
   and five more were found during the 2026-08-21 merge.

## Acceptance Criteria

1. **Zero** files under `docs/kb/execution/tasks/` contain the string
   `⛔ STOP — this specification is superseded` — verified by `grep -rl`, expected count **0**.
2. All **25** files carry a re-specification note naming `M2-C12` and the date.
3. `grep -riE 'react|vite|mantine|tanstack|zustand|react hook form|\bzod\b|\.tsx|jsx' ` over the
   25 returns **only** matches that are explicitly historical — each one inside a sentence that
   marks it as the superseded past (e.g. "the React specification this replaces"). No match
   remains as a live instruction.
4. Every re-specified file names its Angular equivalents from the translation table, and every
   path it gives under `frontend/` is `frontend/nexgen-web/…`.
5. Every command quoted in the 25 appears verbatim in KB-083's verified Angular table.
6. **`depends_on`, `business_rules`, `priority`, `estimate` and gate are byte-unchanged in all
   25** — proved by diffing those frontmatter keys before and after, not by assertion.
7. Every `file:line` citation into `V.SMART/` (the Blazor evidence) is byte-unchanged, or its
   change is individually justified in the Execution Record.
8. `M2-C11` is **not** silently re-specified: its banner is replaced by a statement of **Q-38**,
   it stays `Blocked`, and the owner is named.
9. The 25 tracker rows state their real remaining blocker; none still cites supersession.
10. `dependency-graph.md` contains no description of the M2-C tree as React-shaped.
11. The diff touches **only** `docs/kb/` — proved by `git diff --stat master...HEAD -- . ':(exclude)docs'`
    returning empty.
12. Every re-specified file still satisfies KB-090's required section set.

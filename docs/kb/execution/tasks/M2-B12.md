## Task Objective

Make document-number allocation **race-safe and idempotent before the first
document-creating HTTP endpoint exists**, without changing a single user-visible document
number format.

The work is deliberately split into three sequential steps — *find out what the code
actually does*, *find out what the live databases actually enforce*, then *fix it with
evidence in hand*. No remedy is pre-committed by this parent file. Choosing one is
[M2-B12-03](M2-B12-03.md)'s job, and it may only choose after
[M2-B12-01](M2-B12-01.md) and [M2-B12-02](M2-B12-02.md) have supplied the facts.

## Why This Task Exists

**R-12 — document numbering race condition. Classified `Inferred (high confidence)` in
[KB-060](../../risks/technical-debt-register.md), and it stays `Inferred` until this task
produces evidence.** The register's recorded action is exactly the three steps below:
*"Verify against the live schema for unique constraints (Q-10). Replace with a DB sequence
or a `sp_getapplock`-guarded allocation. Add idempotency keys on create endpoints."*

### The concurrency argument, stated plainly

Blazor Server serialises a user's interactions over a single circuit, and the product has a
small enough concurrent-user population that two document creations rarely overlap within
the few milliseconds of the read-then-insert window. **That is the only thing currently
holding the invariant.** It is a property of the *host*, not of the *code*.

**An HTTP API removes it.** A React client can fire concurrent `POST`s; a retried request
after a timeout produces a second create; a load test produces hundreds. The window that
Blazor Server made statistically invisible becomes routinely reachable.

> **Therefore this task must land before the first document-creating endpoint is merged.**
> Not before the first *controller* — [M2-D01](M2-D01.md) exposes Currency, a master, and is
> unaffected — but before any endpoint that allocates a DC, invoice, PO, GRN, SCN, route
> card, job order or estimate number. In M2 that means before
> [M2-D02-02](M2-D02-02.md) if Customer Master turns out to allocate a number, and
> unconditionally before M3-5 (documents).

### Why the risk is not what the register says it is

**New finding, Confirmed, re-verified 2026-08-12 — record it, do not repeat the old
claim.** R-12 says the ~20 repositories use `SELECT TOP 1 … ORDER BY … DESC` with
*"no lock, no `UPDLOCK`"*. That is **wrong on the lock hint**:

| Claim in R-12 | What the code actually does |
|---|---|
| "no lock, no `UPDLOCK`" | **37 of 38** raw-SQL numbering statements carry `WITH (UPDLOCK, ROWLOCK)`. Example: `V.SMART/V.SMART.Shared/Repository/SalesAndLabourRepository/SalesDCRepository/MfgDcRepository.cs:31-38` |
| "no serializable transaction" | **Correct.** `HOLDLOCK`, `IsolationLevel`, `Serializable` and `sp_getapplock` return **zero** matches across `V.SMART/` (Confirmed, negative result) |
| "no DB sequence" | **Correct.** No `CREATE SEQUENCE`, no `HasSequence` |
| "~20 repositories" | **Undercount.** 36 repository files, 38 raw-SQL sites, plus 7 lock-free LINQ sites and 4 allocation-table read-modify-write methods |

`UPDLOCK, ROWLOCK` without `HOLDLOCK` and without an enclosing transaction does **not**
close the race: a `ROWLOCK` U-lock is a row lock, not a range lock, so it cannot block the
*insert of a new row* that a competing session is about to perform — and outside an explicit
transaction the lock is released when the statement completes. The hint makes the code
*look* protected while providing close to nothing. **That is worse than no hint at all,
because it has evidently already persuaded at least one reader** — see the comment
`// Safely fetch the latest QuoteNo with locking to prevent concurrency issues` at
`V.SMART/V.SMART.Shared/Repository/OutSourcingRepository/DebitNote_Repository/DebitNoteRepository.cs:32`.

Preserve R-12's `Inferred (high confidence)` classification. Nothing found so far is a
observed duplicate; it is a reading of the code. Only [M2-B12-02](M2-B12-02.md)'s duplicate
scan can move it to `Confirmed` — or refute it.

### Q-10 is unresolved and reframes the task

**Q-10** ([KB-004](../../open-questions.md)): *do the document-number columns carry unique
constraints in the live databases?* [KB-004](../../open-questions.md) records this as
"Not visible in the EF model".

**That is not quite right either (new finding, Confirmed).** The EF model declares exactly
**one** document-number unique index:

```
V.SMART/V.SMART.Shared/Data/ApplicationDbContext.cs:579-582
    //Unique MfgQuoteNo
    builder.Entity<MfgQuote>()
            .HasIndex(q => new { q.QuoteNo, q.Suffix })
            .IsUnique();
```
confirmed present in `V.SMART/V.SMART.Shared/Migrations/ApplicationDbContextModelSnapshot.cs:19817-19818`.
The model snapshot contains six `IsUnique()` calls in total; the other five are
`User.EmailId`, `User.UserName`, `AssmblyDef(AssmblyID, ItemId)`,
`AssemblyDefLabour(AssmblyID, ItemId)` and an `InspectId` — **none of them a document
number**. So `MfgQuote` is the sole protected document series in the model, and every other
series — DC, invoice, PO, GRN, SCN, route card, job order, estimate, debit/credit note — is
unprotected as far as the model is concerned.

This matters because it changes what the task is:

> If the live databases have no unique constraint on those columns, **duplicates may already
> exist and nobody would know.** The task is then *detection plus prevention*, not
> prevention. [M2-B12-02](M2-B12-02.md) is therefore required to run a duplicate-detection
> query over existing rows, not merely an `sys.indexes` check.

And because multi-tenancy is **database-per-tenant** (`ITenantProvider` /
`ITenantDbContextFactory`,
`V.SMART/V.SMART.Shared/Services/MultiCompanyService/ITenantProvider.cs`,
`.../ITenantDbContextFactory.cs`; [KB-014](../../architecture/multi-tenancy.md)),
"check the live database" means **checking a named tenant**, and the answer may differ per
tenant. This is the same hazard Q-14 records for stored procedures. A single tenant's
answer is a sample, not a conclusion.

## Rollup Gate Contribution

This task does not own a numbered **G2** exit criterion in
[KB-080 §9](../README.md#exit-gate--g2) — it predates none of them. It is a **precondition
on the first document-creating endpoint**, and the gate reviewer should treat it that way:
if any endpoint merged during M2 allocates a document number and M2-B12-03 has not landed,
G2 does not pass regardless of what the criteria list says.

```
M2-B07 ──► M2-B12-01 ──► M2-B12-02 ──► M2-B12-03 ──┐
             (INV-012)      (Q-10)        (R-12)   │
                                                   ▼
                          any endpoint that allocates a document number
                                     (M3-5 onward)
```

Three caveats the gate reviewer must hold:

1. **The numbering format is a compliance surface, not a naming convention.** Document
   numbers appear on statutory documents — tax invoices, e-way bills, delivery challans.
   Their shape, including the financial-year suffix produced by
   `V.SMART/V.SMART.Shared/Services/FinancialYearHelper.cs:11-17`, is referenced by
   customers, by auditors and by the e-Invoice/e-Way gateway payloads under
   `V.SMART/V.SMART.Shared/.../E_Invoice/` (INV-015, *Scheduled*). **Changing the shape is a
   compliance change, not a refactor.** A remedy that produces correct, unique, gap-free
   numbers in a *different* format is a failed remedy. This is the single most important
   preserved behaviour in this batch, and it constrains the choice in M2-B12-03: a plain
   `CREATE SEQUENCE` cannot by itself reproduce a per-suffix, per-`DcType`,
   `BookTypeDc`-dependent series.
2. **A green build proves nothing here.** The failure mode is a duplicate produced under
   concurrency; it cannot be observed by compiling, and it cannot be observed by a
   single-threaded manual test. If the concurrency test does not run against a real
   database, the change is **unverified** and must be reported as such.
3. **M2-B12-02 hands work to a human and waits.** A session that reports Q-10 "answered"
   without a DBA-returned result set has not completed the task. Inventing a plausible
   schema answer is the specific failure this task tree is shaped to prevent.

## Existing Behaviour to Preserve

Stated once here, inherited by all three children:

1. **Every user-visible document number format, byte for byte.** Including the
   financial-year suffix, the separator, the zero-padding (or lack of it — most series pad
   nothing, e.g. `MfgDcRepository.cs:31-38` returns a bare integer string), and the
   `BookTypeDc`-dependent shared-vs-separate series logic in
   `CommonService.cs:1883-1907`.
2. **The financial-year boundary rule.** April starts the year:
   `FinancialYearHelper.cs:13` — `date.Month >= 4 ? date.Year : date.Year - 1`. Note that
   `CommonService.cs:1850` computes the same thing with `now.Month > 3`, a *different
   expression of the same rule*. They agree today. M2-B12-01 must record that there are two
   independent implementations, because a remedy that unifies them could silently move a
   boundary.
3. **The `BookTypeDc` sharing modes.** `bookTypeDc` 1, 2 and 3 select whether MFGDC,
   LABOURDCOUTGOING and SUBCONDCOUT draw from separate, partially shared or fully shared
   series (`CommonService.cs:1883-1907`). Whatever replaces the allocator must reproduce all
   four branches, including the `bookTypeDc <= 0` fallback at `:1928-1944`.
4. **Manual number entry stays possible.** `MfgDcService.cs:815` branches on
   `mfgDcVM.IsManualDcNo`; when a user supplies the number, the code *records* it into the
   allocation table rather than allocating. A remedy must not force auto-allocation.
5. **Existing application-level duplicate checks keep their current semantics** unless
   M2-B12-03 deliberately changes them and says so. Note `MfgDcService.IsDuplicateDcNoAsync`
   (`:771-790`) scopes the check by `CustId`, so the *same* DC number for two different
   customers is not currently flagged — which means an unqualified unique index on
   `(DcNo, Suffix)` would reject data the application presently accepts. **M2-B12-02 must
   measure this before M2-B12-03 proposes any constraint.**

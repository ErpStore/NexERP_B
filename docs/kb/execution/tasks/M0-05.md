## Task Objective

Remove the published credentials from the repository's committed history so that
`git grep -l "<credential>" HEAD` returns nothing, and so that a fresh clone of the public
remote contains no secret at any revision.

Concretely: rewrite the single commit `c12c5b2`, force-push the rewritten history to
`https://github.com/ErpStore/NexERP_B.git`, and coordinate with everyone holding a clone or
a fork.

## Why This Task Exists

Serves the second half of the G0 criterion "No connection string or JWT secret in the
working tree **or** in `git grep … HEAD`"
([KB-080 §7](../README.md#exit-gate--g0)), and the "Purge from git history
(`git filter-repo`)" clause of
[KB-060 R-01](../../risks/technical-debt-register.md#r-01--live-database-credentials-committed-to-source-control).

**Be honest about what this task is worth.** Three framing facts, all Confirmed:

1. **The credentials are already harvested — assume it.** The remote is public
   (`git ls-remote` succeeds with no authentication, INV-029, re-verified 2026-08-12).
   Public repositories are scraped continuously and automatically. Anyone who cloned,
   forked, or scraped it before the rewrite still holds every secret, and GitHub itself may
   retain the old objects in cached views and in forks.
   **Rotation (M0-04) is the real remedy. This task is damage limitation, not a fix.**
   [KB-080 §7 Risks](../README.md#risks) states exactly this: "assume the secrets are
   already harvested and rotate regardless".
2. **The rewrite itself is trivially simple.** History is exactly **one commit** —
   `git log --oneline` returns only `c12c5b2 "Add project files."` (Confirmed, re-verified
   2026-08-12). There is no long chain to rebase, no merge topology, no signed-commit
   problem. Mechanically this is among the easiest history rewrites possible.
3. **The consequence is not simple.** A force-push rewrites a **public** repository. Every
   existing clone diverges. Every open pull request against the old history breaks. Every
   fork keeps the old objects — and the credentials in them — regardless of what happens to
   the upstream repository. That asymmetry (easy to do, impossible to fully undo elsewhere)
   is why this task carries coordination weight far out of proportion to its technical size.

## Implementation Steps

1. **Verify the prerequisites are genuinely met, and stop if they are not.**
   - Read `docs/runbooks/credential-rotation.md` and confirm its **verification checklist is
     signed** — a name and a date. If it is not, this task is **Blocked**. Say so and stop.
     Do not proceed on an assurance that rotation "is in progress".
   - Confirm M0-03-01, M0-03-02 and M0-03-03 are all Completed.
   - Confirm Q-19 has an answer in `docs/kb/open-questions.md`.
2. **Take a full backup before touching anything.** Clone the repository to a separate
   location with `git clone --mirror`, and keep it until the rewrite is confirmed good. A
   mirror clone is the only cheap undo a history rewrite has.
3. **Census.** Enumerate forks and clone-holders (see *Investigation Requirements*). Write
   the list into the deliverable document. If it cannot be completed, record what is unknown
   — do not leave the gap implicit.
4. **Announce, before rewriting.** Send written notice to every clone-holder: the date and
   time of the force-push, the instruction to **delete and re-clone** (not `pull`, not
   `fetch --force` unless they know exactly what they are doing), and a warning that pushing
   an un-rebased local branch afterwards will **reintroduce the secrets**.
5. **Check tooling.** `git filter-repo --version`. If it is absent, either install it (a
   deliberate, recorded environment change) or use the single-commit fallback in step 6b.
6. **Rewrite.** Two viable approaches for a one-commit history — choose one and justify it:
   - **6a. `git filter-repo`** — the tool KB-060 R-01 names. Use `--replace-text` with an
     expressions file listing the literal strings to redact.
     **The expressions file contains the secrets and must never be committed**: create it
     outside the repository, and delete it afterwards.
     Note that `git filter-repo` refuses to run on a non-fresh clone by default; work from
     the mirror clone taken in step 2, or pass `--force` knowingly.
   - **6b. Orphan re-root** — because there is exactly one commit, `git checkout --orphan`
     from the cleaned working tree, commit, and reset `master` to it. Simpler, no extra
     tooling, and produces a genuinely clean single commit. Its downside is that it discards
     the original commit's metadata, which for a commit titled "Add project files." costs
     almost nothing.
7. **Verify the rewrite locally, before pushing.**
   - `git log --oneline` — confirm the expected commit count.
   - `git grep -l "aDMIN@123" HEAD` — must return nothing.
   - Repeat for the production host, the production password, and the gateway strings.
   - Confirm the checked-out working tree is content-identical to what it was before.
   - `dotnet build V.SMART/V.SMART.Api/V.SMART.Api.csproj` — must still report 0 errors.
     A rewrite that loses a file will show up here.
8. **Force-push**, performed by the GitHub admin, with `master` temporarily unprotected:
   `git push --force origin master`. Restore protection immediately afterwards. Record who
   did it and at what time.
9. **Verify on the remote.** From a **completely fresh clone** into a new directory, re-run
   the `git grep … HEAD` checks. Verifying only in the local repository proves nothing about
   what the remote serves.
10. **Handle branches.** Rebase or re-create every branch that was based on the old root.
    List each and its disposition.
11. **Handle forks.** Contact each fork owner. Record every fork that could not be cleaned as
    an accepted residual risk with a named accepter.
12. **Write the residual-risk record** into `docs/runbooks/credential-rotation.md` (extending
    M0-04's document rather than creating a competing one): what was purged, when, by whom,
    what remains exposed, and the explicit statement that rotation is what makes it harmless.
13. Update KB-060, KB-003, and this task file. Report.

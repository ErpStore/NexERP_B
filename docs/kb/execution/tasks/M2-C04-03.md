## Why This Task Exists

- **The empty/loading/error triad is a requirement of every screen, not a polish pass.**
  [KB-051 §State patterns](../../frontend-new/design-system.md#state-patterns) specifies seven
  distinct states, including the distinction between "no data yet" and "filtered out". If
  these components do not exist before feature work starts, ~140 screens each invent their
  own — and most will ship with a spinner on a blank page and a generic "An error occurred".
- **KB-051 §Principle 6 is explicit: "Errors are specific."** The server's business-rule
  message must be shown verbatim (KB-050 §Error handling: a 409 surfaces "the server's
  message verbatim — these strings are product UX"). `ErrorState` and `InlineAlert` are where
  that promise is either kept or quietly broken.
- **`ConfirmDialog` with a required reason encodes a real ERP obligation.** `BsModal.razor`
  is already "confirm dialog, optional reason textbox" (Confirmed, KB-015 §Shared components),
  and **BR-SO-003 (Confirmed)** requires a **mandatory cancellation reason** when cancelling a
  Sales Order or a line. The React dialog must support that capability — while the *rule*
  (which actions require a reason, and the downstream-transaction checks) stays server-side.
- **Modals versus drawers is a stated design rule, and it is about work, not taste.**
  KB-051 §Do not: "Use modals for anything that needs the list behind it — use a drawer." An
  operator reconciling a list against a record needs both visible. Providing both primitives,
  with guidance, is what makes that rule followable.
- **Accessibility is hardest exactly here.** Focus trapping, focus restoration, `Esc`
  handling and live-region politeness are the parts of a design system most often wrong. KB-051
  commits to them explicitly; this task is where they are implemented once instead of 140
  times.

## Target Result

### Overlays

| Component | Contract |
|---|---|
| `Modal` | Sizes `sm/md/lg/full`. Focus trapped; focus restored to the invoker on close; `Esc` closes; scroll locked behind it; `role="dialog"` + `aria-modal` + a labelled title. Rendered in a single portal root. |
| `Drawer` | Right-side, resizable, for record detail **without losing list context** — the KB-051 rule that a modal must not be used when the list behind it matters. Same focus contract as `Modal`. Width persists per user, locally for now. |
| `ConfirmDialog` | Title, body, confirm/cancel labels, a `destructive` variant, and an optional **required reason** textarea with its own validation (BR-SO-003 capability). Confirm is disabled until a required reason is non-empty. `Esc` and the backdrop map to **cancel**, never to confirm. |
| `Popover`, `Tooltip`, `ContextMenu` | Keyboard reachable; `Tooltip` also opens on focus, not hover alone; `ContextMenu` is reachable via a keyboard affordance, because a right-click-only menu is inoperable by keyboard. |

### Feedback

| Component | Contract |
|---|---|
| `Toast` | Mantine Notifications. Success auto-dismisses at 4 s; **error is sticky with an explicit dismiss** (KB-051). Announced via a polite live region. Never carries the only copy of an error a user must act on. |
| `InlineAlert` | `info / warn / error / success`. Icon **plus** text — never colour alone. Renders the server's message verbatim for business-rule 409s. |
| `BusyOverlay` | Region-scoped by default; a `fullPage` escape hatch that must be justified at the call site. Announces busy state; does not steal focus. |
| `Skeleton` | Shape-matched placeholders, composable into a layout that matches the final one — "never a spinner on a blank page". |
| `ProgressBar` | Determinate and indeterminate; `role="progressbar"` with correct `aria-valuenow`/`min`/`max`. |
| `EmptyState` | Illustration + explanation + primary action. **Two distinct variants**: "no data yet" (with a create action) and "no results for these filters" (with Clear filters). |
| `ErrorState` | The server's message **verbatim**, the `traceId` (copyable), and a Retry action. It must be impossible to render it with a generic message — the message prop is required and has no default. |
| `PermissionDeniedState` | Explains **which screen right is missing**, inline. Renders no retry (retrying does not grant a right) and no navigation away. Purely presentational: it takes screen and right as props and reads no store. |

## Implementation Steps

1. **Read KB-051 §Overlays/§Feedback/§State patterns and the three Razor references.**
   Record what `BsModal` and `ProcessingOverlay` actually do before designing the replacements.
2. **Create the branch** `migration/M2-C04-03-feedback-primitives`.
3. **Build `Modal` first** — it is the focus contract the drawer and confirm dialog inherit.
   Verify: trap, restore, `Esc`, scroll lock, `aria-modal`, labelled title, single portal root.
4. **Build `Drawer`** on the same contract, plus resize (keyboard-resizable too — a
   drag-only handle is inaccessible) and local width persistence.
5. **Build `ConfirmDialog`** on `Modal`. Support `reasonRequired`; disable Confirm until the
   reason is non-empty; map `Esc` and backdrop to **cancel**. Add a `destructive` variant that
   changes emphasis, not the keyboard behaviour. Use `FormField` + `Textarea` if M2-C04-02 has
   landed, otherwise a bare Mantine textarea with a `TODO`.
6. **Build `Popover`, `Tooltip`, `ContextMenu`** with keyboard parity. `Tooltip` content must
   never be the only place information exists; document that.
7. **Mount the notifications provider** in `providers.tsx` and build the `Toast` API as a thin
   typed wrapper (`toast.success`, `toast.error`, `toast.info`) so call sites never touch
   Mantine's API directly — that is what makes a future library change survivable.
8. **Build `InlineAlert`**, icon + text, with a `dismissible` option.
9. **Build `BusyOverlay`, `Skeleton`, `ProgressBar`.** `Skeleton` must compose: a
   `SkeletonTable` and a `SkeletonForm` preset save every future screen from inventing one.
10. **Build `EmptyState`, `ErrorState`, `PermissionDeniedState`.** Make `ErrorState`'s
    `message` prop **required with no default**, so "An error occurred" cannot be reached by
    forgetting an argument. Add a copy-to-clipboard control for the `traceId` — support asks
    for it and retyping a GUID is a poor use of an operator's time.
11. **Write the tests** in [Testing](#testing), including the focus-restoration and
    live-region tests.
12. **Write the usage documentation**: when to use a modal versus a drawer, when a toast is
    insufficient, and the `EmptyState` variant rule.
13. **Verify** with the M2-C01 command set, update docs, amend INV-006, review, commit.

## Business Logic

**Newly introduced — presentation behaviour only.**

The behaviour added is feedback presentation: overlay lifecycle, focus management, message
display and state vocabulary.

**No ERP business rule is implemented.** In particular, **BR-SO-003 is not implemented
here.** `ConfirmDialog` provides the *capability* to require a reason; the rule — that
cancelling a Sales Order or a line requires a reason, that downstream transactions must be
checked first (`IsPoTransactionsMatchedAsync`, `CanSalesOrderItemCancelCheckAsync`), and that
balance quantities are reverted — is server-side and stays there. A screen decides to pass
`reasonRequired`; the server decides whether the cancellation is legal.

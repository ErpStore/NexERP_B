> **Re-specified for Angular on 2026-08-22 by [`M2-C12-04`](M2-C12-04.md).** The ⛔ STOP banner
> that stood here is removed **in the same change that removed the stack-specific instructions it
> guarded**: this file no longer specifies the ADR-003 stack.
> [`ADR-007`](../../decisions/ADR-007-angular-stack.md) is the governing stack decision —
> **Angular 22.x + PrimeNG** — and [KB-050](../../frontend-new/react-architecture.md), rewritten
> for Angular by `M2-C00`, is the structure this shell is built into.
>
> **The specification this replaces is not deleted from the record.** Its *intent* survives
> unchanged, and most of this file was never framework-specific: the region-by-region layout, the

> verified Angular command set of [KB-083](../prompt-template.md#verified-repository-commands).

## Objective

Build the layout and composition skeleton of `DocumentEditorComponent<THeader, TLine>` — the
single standalone component that all ~65 document editors are configurations of — together with
the `DocumentEditorConfig` contract that drives it.

## Scope

- The page skeleton: page header (title, breadcrumbs, status badge), header form region,
  `LineItemGrid`, totals panel region, side region (attachments / terms / remarks / audit trail),
  sticky command bar.
- `DocumentEditorConfig<THeader, TLine>` — the object a feature module supplies.
- Mode handling: `create` / `edit` / `view`, consolidating the existing create / update / details
  routes into one route with a mode
  ([KB-050 constraint 2](../../frontend-new/react-architecture.md#design-constraints-from-the-existing-system)).
- Typed Reactive Forms wiring for the header form, and the dirty-state navigation guard as a
  functional `CanDeactivateFn`.
- Save / Save+New / Cancel, and the layout slots into which M2-C08-02 (totals) and M2-C08-03
  (commands) plug.

## Out of Scope

- The calculate call and totals semantics — **M2-C08-02**.
- Workflow command dispatch — **M2-C08-03**.
- Any actual document module — **M3-5** and later. `MfgPOUpsert.razor` is read-only reference.
- Re-implementing `LineItemGrid` or `RecordPickerDialog`; both are composed whole.
- Any second component library, dialog implementation or form library.

## Why This Task Exists

- The one-editor rule — *"One `DocumentEditor` component configured 65 ways, not 65 bespoke
  editors"* — predates the framework switch and is unchanged by it. The rule is only real once the
  component and its configuration contract exist; until then every module team will build its own.
- [KB-051 principle 5](../../frontend-new/design-system.md#principles) requires the *"same page
  skeleton on all 150 screens: header → filters → content → footer actions."* This task makes that
  structural rather than aspirational for the document half of the app.
- It replaces four existing shared components at once — `PageHeader.razor`,
  `UnsavedChangesModal.razor`, `ProcessingOverlay.razor`, `SmartBackButton.razor` — with one
  composed shell.
- It unblocks both siblings and, through them, wave M3-5.

  universal and which are optional. Sample at least five of the largest, listed with their
  measured sizes in [KB-015](../../architecture/frontend-architecture-existing.md#page-anatomy):
  `LabourDcOutgoingUpsert.razor` (6,528), `ItemUpsert.razor` (4,731), `PurchPOUpsert.razor`
  (4,620), `MfgInvUpsert.razor` (4,431), `MfgPOUpsert.razor` (4,383). Answer, with `file:line`
  evidence:
  1. Do all have exactly one line grid, or do some have two or more?
  2. Which have tabbed header sections rather than one flat form?
  3. Which show a totals panel at all? (Not every document is priced.)
  4. What is the actual command-bar vocabulary across them, beyond Save/Cancel?
  5. Which need a second-level child grid (line → sub-line)?

  If the answer to (1) or (5) is "some do", the config contract must accommodate it **now** —
  discovering it in M3-5 means reworking the shell after screens depend on it.
- **Record negative results.** "No sampled screen has two line grids" is a finding that simplifies
  the contract, and it must be written down so nobody re-investigates.
- **Do not** extract business logic from any sampled page. Structural survey only.

## Target Result

```html
<app-document-editor
  [config]="salesOrderEditorConfig"
  mode="edit"
  [id]="poId" />
```

```
┌ PageHeader ── title · breadcrumbs · status badge · document number · header actions ─┐
├ HeaderForm ──── typed Reactive Form, FormLayout sections, collapsible                │
├ LineItemGrid ── M2-C07, virtualised, keyboard-first, upstream-pull affordance        │
├ TotalsPanel ─── SLOT, read-only  (filled by M2-C08-02)                               │
├ SideRegion ──── attachments · terms · remarks · audit trail  (tabs or accordion)     │
└ CommandBar ──── sticky: [Cancel]  …workflow command SLOT (M2-C08-03)…  [Save] [Save+New]
```

- **`DocumentEditorConfig`** declares: document title and noun, the resource slug, the header form
  shape and field layout, the line column set, the load/save/calculate/command operations, the
  side regions to show, the workflow commands to offer, and the totals descriptor. Everything
  module-specific is data.
- **Modes.** `create` starts empty with the first field autofocused; `edit` loads by id; `view`
  renders everything read-only with commands still available where the server permits.
- **Dirty guard.** A functional `CanDeactivateFn` registered on the route intercepts navigation
  with unsaved changes; the command bar shows "Unsaved changes"; a `beforeunload` listener is also
  wired, and only while dirty.
- **Saving does not block the page.** Footer actions disable, the Save button shows an inline
  spinner, and the rest of the page remains readable.
- **Layout is responsive** per [KB-051](../../frontend-new/design-system.md#responsive-behaviour),
  and below 768 px the editor renders read-only rather than a broken editing surface.
- **Focus is never lost.** After a save, focus returns to a deterministic anchor; after a
  validation failure it moves to the first invalid field and the region containing it opens.

## Frontend Changes

| Aspect | Detail |
|---|---|
| **Route** | The shell is designed for **one** route per document type carrying a mode — e.g. `/sales/orders/new`, `/sales/orders/:id`, `/sales/orders/:id?mode=view`. This task defines the pattern and a test harness route; **no real document route is registered**, because no document module exists in M2. |
| **Component** | Standalone `DocumentEditorComponent<THeader, TLine>` (selector `app-document-editor`) under `frontend/nexgen-web/src/app/shared/components/document-editor/` (**TO BE CREATED**), composing `LineItemGrid` (M2-C07), `RecordPickerDialog` (M2-C06) and M2-C04's form and feedback primitives. |
| **API integration** | Config-supplied operations executed through a typed service over `HttpClient`. A mutation is followed by an **explicit `refresh()`** of the affected service — there is no cache to invalidate and no cache surgery to get wrong ([KB-050 §Data-fetching conventions](../../frontend-new/react-architecture.md#data-fetching-conventions)). **No optimistic update** for anything touching money, stock or document status (BR-CALC-001, BR-STK-001). |
| **State** | Header and lines in one typed Reactive `FormGroup` (the lines as a `FormArray` handed to `LineItemGrid`). Server state in the editor's own service, held in signals and exposed read-only via `asReadonly()`. Section open/closed state persisted per document type in local storage. No global state service is introduced. |
| **Validation** | Angular `Validators` built from the config's field descriptors, with shapes **generated from OpenAPI**, mirroring `DataAnnotations` **for UX only**. A 400 `errors` dictionary maps onto form controls by key, opening and focusing the first offending section. Cross-field and cross-row rules are the server's. |
| **Permissions** | Actions enabled/disabled from M2-C02's permission service — a UX affordance only. The server enforces independently (ADR-004). A 403 renders inline, not as a redirect; read `screen`/`right` from the problem extensions ([KB-050 §Error handling](../../frontend-new/react-architecture.md#error-handling)). |
| **Loading state** | Skeleton mirroring the final layout: header-form skeleton, grid skeleton, totals skeleton. Saving disables footer actions and shows an inline spinner on the button; **the page is never blocked** — a deliberate change from `ProcessingOverlay.razor`. |
| **Empty state** | `mode="create"` is not an empty state: it renders the form with one empty line row and the first header field focused. A document that fails to load renders `ErrorState`, not an empty editor. |
| **Error state** | Load failure → full-region `ErrorState` with the server message, `traceId` and Retry. Save failure → toast plus inline field errors. 409 → the server's `title` **verbatim** (the shared handling M2-C08-03 relies on). |
| **Accessibility** | One `<h1>`; regions are `<section>` with accessible names; the command bar is a labelled toolbar; the dirty state and save outcome are announced via `aria-live="polite"`; focus moves to the first invalid field on validation failure and returns to a deterministic anchor after save; the whole editor is operable with no pointer; status is icon + text, never colour alone. |
| **Responsive behaviour** | ≥1440: 3-column header form, totals panel beside the lines. 1024–1439: 2-column form, totals below the lines. 768–1023: 1-column form, side region as an accordion. <768: **read-only** rendering per [KB-051](../../frontend-new/design-system.md#responsive-behaviour). |

## Business Rules

**Newly introduced — layout and form plumbing only, with justification.**

`DocumentEditor`'s shell is new code: composition, modes, dirty-state guarding, validation
display, focus management.

**No ERP business rule is implemented client-side by this task.** Specifically the shell does not:

- compute or adjust any total, tax, discount or round-off — that is BR-CALC-001 and M2-C08-02's
  wiring to the server;
- decide any document status or permitted transition — that is M2-C08-03's command dispatch;
- interpret `rowEvent` from `LineItemGrid` — it forwards the event to a config-supplied operation
  and applies the result;
- derive a document number, a financial-year suffix or any default from another field — all
  server-side ([KB-050](../../frontend-new/react-architecture.md#what-is-deliberately-not-rebuilt-in-the-spa));
- contain any module-specific field name, status value or endpoint.

The client-side validators are **shape** validation for immediate feedback. They mirror the
server's `DataAnnotations` and are generated from OpenAPI; they are never the authority.

## Task Objective

Make `V.SMART.Api` and `V.SMART.Web` **refuse to start** when a required secret is missing,
empty, or still set to a known default value. Specifically: startup must throw, with an
actionable message, when `ConnectionStrings:MasterDb` is absent or empty, and — for the API
— when `Jwt:Secret` is absent, empty, shorter than 32 bytes, or equal to any value on a
known-defaults deny-list.

A host that starts with no secret configured, or with a published default secret, is worse
than a host that will not start: the first silently issues forgeable tokens, the second
tells an operator exactly what to fix.

## Why This Task Exists

Serves the *action* half of **R-02**, which reads: "Move to secret storage; rotate; **fail
startup if the secret is missing or is the known default**"
([KB-060 R-02](../../risks/technical-debt-register.md#r-02--jwt-signing-secret-committed)).
Only the last clause is this task's; the first two are M0-03-01 and M0-04.

It also closes a concrete failure mode recorded in
[KB-014 §Problems for a React SPA, item 4](../../architecture/multi-tenancy.md#problems-for-a-react-spa)
(Confirmed): `TenantProvider.GetCurrentTenant()` returns `null` and writes to `Console` when
resolution fails, and `TenantDbContextFactory` then throws a
`NullReferenceException` on `.ConnectionString`
(`V.SMART/V.SMART.Shared/Services/MultiCompanyService/TenantDbContextFactory.cs:19`). A
misconfigured master connection string produces that same shape of failure — a null-reference
deep inside a factory, on the first request, with no diagnostic. Failing at startup instead
converts an unexplained 500 into a one-line operator message.

And it protects the G0 criterion "A fresh environment can be rebuilt from source control
alone… and the app runs against it" ([KB-080 §7](../README.md#exit-gate--g0)). After
M0-03-01 and M0-03-02 the repository contains **no** working configuration by design. The
first person to clone it will get a misconfigured environment. What they see at that moment
is what this task decides.

## Existing Behavior to Preserve

- **The one guard that already exists**, `V.SMART/V.SMART.Api/Program.cs:56-57`
  (Confirmed):

  ```csharp
  var jwtSecret = builder.Configuration["Jwt:Secret"]
      ?? throw new InvalidOperationException("Jwt:Secret is missing from configuration.");
  ```

  It catches `null` but **not** empty string, **not** a too-short value, and **not** the
  known default. Extend it; do not replace its intent, and keep the exception type
  (`InvalidOperationException`) so that any existing operational runbook still matches.
- `V.SMART/V.SMART.Api/Program.cs:60-74` builds `TokenValidationParameters` from
  `signingKey`, `Jwt:Issuer` and `Jwt:Audience`. `Jwt:Issuer` and `Jwt:Audience` are **not
  secrets** and currently have real values in `appsettings.json` (`V.SMART.Api`,
  `V.SMART.Angular`). Validate that they are non-empty, but do **not** put them on a
  secret deny-list.
- `V.SMART/V.SMART.Api/Program.cs:82-83` and `V.SMART/V.SMART.Web/Program.cs:226-227` both
  call `GetConnectionString("MasterDb")` and pass the result straight to `UseSqlServer`
  with **no null check** (Confirmed). A null there does not fail at startup — it fails
  later, obscurely.
- `V.SMART/V.SMART.Api/Program.cs:103` constructs
  `new JwtTokenService(builder.Configuration)` as a singleton. Whatever validation runs must
  run **before** this line, so a bad secret never reaches the token service.
- Do not change the DI graph, the CORS policy (`"AngularDev"`,
  `V.SMART/V.SMART.Api/Program.cs:48-54` — that is M2-A05), Swagger configuration, or the
  middleware order (`V.SMART/V.SMART.Api/Program.cs:113-116`).

## Target Result

Each host performs an explicit, ordered configuration check immediately after
`WebApplication.CreateBuilder(args)` and before any dependent registration. Each failed
check throws a single `InvalidOperationException` naming:

1. the configuration key that failed,
2. why it failed (missing / empty / too short / known default),
3. the exact remediation — the environment-variable name and the
   `dotnet user-secrets set` command.

Rules to enforce:

| Key | Host | Fail when |
|---|---|---|
| `ConnectionStrings:MasterDb` | Api **and** Web | null, empty, or whitespace |
| `ConnectionStrings:MasterDb` | Api **and** Web | it matches a known-default entry (the pre-rotation local-SQLEXPRESS and production strings) |
| `Jwt:Secret` | Api | null, empty, or whitespace |
| `Jwt:Secret` | Api | fewer than 32 bytes in UTF-8 — this is what `SymmetricSecurityKey` + HMAC-SHA256 requires, and it is what the current default value's own text advertises |
| `Jwt:Secret` | Api | it matches a known-default entry |
| `Jwt:Issuer`, `Jwt:Audience` | Api | null, empty, or whitespace |

**The known-defaults deny-list must not be written into the repository as literal secret
strings.** Store the deny-list as **salted-free SHA-256 hex digests** of the offending
values, compare digests, and put a comment naming the source (`KB-060 R-01/R-02`) rather
than the value. This keeps the repository free of the very strings the task is trying to
eliminate, and keeps `git grep -n "Password="` clean. Note in the code comment that a hash
list is a tripwire, not a security control.

   **do not commit the plaintext**, not even in a test fixture, not even commented.
   Comment each digest with its provenance (`// KB-060 R-02 default JWT secret`).
6. Call the validator in `V.SMART/V.SMART.Api/Program.cs` immediately after line 20
   (`var builder = WebApplication.CreateBuilder(args);`) and **before** line 56, so it runs

7. Extend or fold in the existing guard at `V.SMART/V.SMART.Api/Program.cs:56-57` so there
   is exactly **one** place that decides whether `Jwt:Secret` is acceptable. Do not leave

8. Call the validator in `V.SMART/V.SMART.Web/Program.cs` immediately after line 180

   form (`ConnectionStrings__MasterDb`, `Jwt__Secret`), and the `dotnet user-secrets set`

10. Manually test all six paths and record each result:
    - Api with everything set → starts.
    - Api with `Jwt:Secret` unset → throws, message names `Jwt:Secret`.
    - Api with `Jwt:Secret` set to `""` → throws.
    - Api with `Jwt:Secret` set to a 10-character value → throws on length.
    - Api with `Jwt:Secret` set to the KB-060 R-02 default → throws on known-default.
    - Api and Web with `ConnectionStrings:MasterDb` unset → throws, message names the key.
11. `dotnet build V.SMART/V.SMART.Api/V.SMART.Api.csproj` → 0 errors.
